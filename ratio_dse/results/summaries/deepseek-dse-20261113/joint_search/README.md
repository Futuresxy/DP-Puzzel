# 固定面积下的阵列尺寸、精度迁移与供数联合搜索

本轮将精度方案作为给定输入，不设置困惑度或准确率门槛。目的是分析硬件设计的条件收益；没有声称这些迁移方案已通过量化质量验证。所有时间仍为 `analytical_uncalibrated`。

## 范围与复现

```bash
bash ratio_dse/run_joint_dse.sh ratio_dse/results/my-joint-run
python3.11 -m unittest discover -s ratio_dse/tests -v
```

本次完整运行目录为 `ratio_dse/results/deepseek-joint-dse-20261113-v3`。配置和输入/源码/输出指纹保存在 [evidence.json](evidence.json)。默认参数：九种完整多精度 DP、32 种分析用 M/N、V4/V4.1 Flash、四种累计迁移方案、batch 1、2,048-token prefill、4/8/16 TB/s 每 SM 本地读带宽、无上限/150 W DP 预算、单/双输入缓冲。V4 使用 full prefill，V4.1 使用简化 CED。共享基线核心池面积 **496.592553 mm²**，固定 1 GHz、每 SM 四阵列，每阵列总缓冲 64 KiB。面积为 DP 综合面积与基线固定外围面积的解析组合。

有效硬件候选共 **6,752 次评价**，产生 **288 组负载→硬件**和 **1,688 组硬件→迁移方案**比较。面积门槛淘汰的 shape 仍记录在完整运行的 `deployments.json`。配比为共享 DP 的 BF16:MXFP8:MXFP4 吞吐比例，各模式峰值不能相加。

## 三个有用的观察

以下表均为 V4.1 Flash、8 TB/s/SM、双缓冲；shape 指单个 TensorCore，SM 数指已安装数量，时延为建模范围内 GEMM 完成时间。

| 负载 | DP 功率预算 | 构建策略 | 最快配比 | shape | SM 数 | 延时 ms |
|---|---|---|---|---|---:|---:|
| Baseline | 无上限 | 固定阵列 | 1:4:4 | 16×4 | 31 | 54.889 |
| Baseline | 无上限 | 等带宽尽量用满 | 1:2:4 | 4×28 | 29 | 48.865 |
| Baseline | 150 W | 固定阵列 | 1:2:4 | 16×4 | 36 | 68.233 |
| Baseline | 150 W | 等带宽尽量用满 | 1:4:4 | 4×12 | 34 | 69.451 |
| Baseline | 150 W | 带宽预算内所有 shape | 1:2:4 | 4×20 | 33 | 67.194 |
| Step 3 | 无上限 | 固定阵列 | 1:2:8 | 16×4 | 32 | 23.996 |
| Step 3 | 无上限 | 等带宽尽量用满 | 1:2:4 | 4×28 | 29 | 23.586 |
| Step 3 | 150 W | 固定阵列 | 1:2:8 | 16×4 | 32 | 23.996 |
| Step 3 | 150 W | 等带宽尽量用满 | 1:2:4 | 4×28 | 29 | 25.413 |

1. **增加基线 DP 数量能改变最佳配比。** 固定 shape 的基线负载偏好 `1:4:4`；允许每种配比调整 shape 后，`1:2:4` 的 `4×28` 方案更快。该方案安装 29×4×4×28 = **12,992 DP**；原 `1:2:4` 的 `16×4` 方案为 36×4×16×4 = **9,216 DP**。同面积下，更多面积分配给 TensorCore、较少 SM 分摊外围开销，使 DP 数提高约 41%。它的理论 BF16/FP4 峰值分别为 415.744/1,662.976 TFLOP/s，但这不等于实际 GEMM 吞吐。
2. **带宽用满应是受控实验，不能替代运行时选优。** 在 150 W 的基线负载下，保留所有带宽可行 shape 选出 `1:2:4 / 4×20`，其全速最大模式需求只占预算 68%，时间为 67.194 ms；逐配比只留最接近用满的 shape 后，赢家变为 `1:4:4 / 4×12`，69.451 ms。额外 DP 的峰值收益会被并发功率与调度条件改变。`bandwidth_filled` 指各配比在给定离散 shape 集合中的最大需求占比；不是所有候选都精确占满 100%。
3. **精度迁移与 DP 复制是两种可替代的设计选择，其关系受功率约束影响。** Step 3 的固定阵列选择 `1:2:8`；无功率上限时，等带宽下更多 `1:2:4` DP 略快；加入 150 W 后，同一可变阵列方案变慢，而固定阵列 `1:2:8` 在该情景下保持优势。不能只按迁移后的 FP4 MAC 占比提高单 DP 的 FP4 容量。

本轮所有同候选单/双缓冲对照，双缓冲加速范围约 **1.11–1.96×**。这是对指定整轮预取调度的条件结果。有限容量可能使双缓冲减少累加上下文，在其他配置下不能保证加速；实现测试已覆盖该容量权衡。

## 结果解释与边界

- `workload_to_hardware.csv` 固定负载和精度方案选择硬件；`hardware_to_migration.csv` 固定物理部署选择迁移方案。没有质量代价的反向选择只回答计算成本问题，不声称得到部署上的最优量化方案。
- `[bandwidth_feasible, bandwidth_filled]` 使用所有目标精度都满足满速输入需求的硬件门槛；`equal_array` 允许供数不足后等待。两个构建集合并不互相包含，固定阵列可能比严格满速门槛下的设计快。
- 运行时按当前精度的 DP 功率允许完整 SM 并发，空闲 SM 仍计 DP 漏电；实际活跃数量也受 tile 数限制。不同算子/精度可启用不同数量，完整运行的 `winning_operator_breakdown.csv` 单列允许 SM 数、实际活跃最大值、上下文数及缓冲需求。
- 双缓冲采用 K 轮粒度，保留首填、RAW、最后流水排空和写回；预取端口与缓冲到 DP 端口独立，后者假定具备 native 发射宽度。跨波预取和跨请求 A/B 驻留未建模。4×4 广播组间仍无共享。
- 每 SM 的带宽固定，SM 数变化后本地端口总和变化；不等于固定整芯片共享带宽。HBM、通信、非 GEMM、在线量化/scale 生成及 SRAM/互连功率不在本轮边界内。
- 精度迁移保持 useful MAC 总量，改变逐精度分布、原生 K 请求数、填充和数据字节。扩大阵列的频率、端口与布线成本尚未经过阵列实现验证；新增 shape 没有直接实测 PPA。

## 检查

31 项回归通过；独立 bank/RAW 事件参考核对 500 组随机参数×两种缓冲模式。另从导出的 CSV 独立复核全部 6,752 项的面积、功率、容量、时间分解，以及全部正反向比较的最小时延和最小 DP 能耗；运行输入、源码和输出 SHA-256 全部匹配。原有样例仍通过，历史串行路径 1,296 个候选的时间、功率、能耗及 useful/issued MAC 与原结果逐字段相同。这些是模型实现检查，不能替代硬件准确率校准。
