### 哪里有余量

没有整个数据级具备可直接借用的余量。已通过的典型旁路为：

- C raw 在 S2/S3/S4 的传递：最差约 +0.515～+0.516 ns。
- S5 C magnitude：+0.237425～+0.466915 ns；C anchor：+0.184029～+0.236047 ns。
- S5 C LZD 的 z 输出仍有 −0.037716～−0.009831 ns，不能把整个 C 解包都标为通过。
- S6→S7 common anchor 传递：+0.500805～+0.517037 ns；其他 type/special 传递也有较大余量。

这些余量位于与主数据并行的支路，不可直接相加、也不能“借给”无依赖关系的乘法/规约链。
在保持 L8 的前提下，可考虑利用 C 的提前传递阶段做预分类/子正规检测，或利用指数旁路准备 S8 的指数常量；但会调整“C 在 S5 解包”的内部合同，须同步 spec/CModel/断点验证。

## 保持 8 级的优化方向（未实施、未宣称达标）

各级都违例仅证明当前 RTL/映射/层级/预算下未达标，不证明 12nm 或八级架构的物理极限。
DC 可能为面积回收非最差路径的余量；当前 slack 排名不能替代每项结构修改后的重测。

1. **先改 S4、S7 的多操作数规约。** 当前树已平衡，但每层仍完成一次宽位进位传播。
   最差路径上 S4 的 lane_sop_tree 入口到出口约 0.675990 ns；S7 final_sop_tree 约 0.680052 ns。
   优先评估 3:2 CSA/压缩树，把多项压成 sum/carry 后只做一次最终并行前缀加法。
   Kogge–Stone 偏重逻辑深度，Brent–Kung/Han–Carlson 可作为面积/扇出对照；实际优势取决于库映射，显式 RTL 不自动保证更快。
   保留二补码符号扩展、完整自然增长位、N=1 和奇数项语义；不是把每个 `+` 都机械替换成更大的前缀网络。
2. **清除控制信号进入长算术链的附加依赖。** 最差 S8 起点是 `c_type_q[6]`，不是 sum_q。
   `float_sum = integer ? 0 : sum_q` 使类型控制先穿过隔离，再走完整 FP32 转换。
   可评估在 S7 寄存边界前完成浮点支路隔离，或采用独立浮点寄存使能并保留 INT bypass；必须实测对 S7 和切换活动的影响。
   S6 类似，应让 INT 结构落位与浮点 MAX/shift 分开到末端选择，降低 datatype 对整个浮点链的控制依赖，同时保持整数模式的 anchor/trace 合同。
3. **缩短 S3 的 E pair 链。** 当前符号转换→pair sum→abs→`pair_abs!=0`→delta 选择→移位→恢复符号。
   `pair_abs==0` 时幅值移位输入本身为零；可验证移除非零检测对 shift control 的依赖，及 signed pair/符号恢复的融合实现。
   必须保持幅值 RTZ，不能用普通算术右移改变负数截断。
4. **S2 优化布局展开与 MAX。** 实测最差路径上布局展开约 0.103 ns、指数 bank 约 0.145 ns、lane MAX 约 0.344 ns、group MAX 约 0.122 ns。
   评估与 S1 解包并行的格式预译码、候选 active 提前生成、比较和选择并行化；避免在 S1 已违例的路径上串入更多计算。
   当前 MAX 已平衡，重点是 active/mux/比较串联及过细层级的优化边界。
5. **S5/S8 减少串行算术。** S5 的代表路径为组加法约 0.173 ns、scale 乘法约 0.289 ns、后续 abs/检测链；S8 LZD 之后还有约 0.424 ns 转换逻辑。
   评估条件取负/abs 融合、舍入 increment 与 exponent carry 并行准备、带 sticky 的有限范围移位，以及按范围推导替代 32-bit integer 控制。
   不改变共享 15×9 scale 乘法器、两个 RTZ 点或 FP32 RNE/下溢语义。

### 何时重新切流水

- 不能直接把 S8 LZD 前移到现有 S7：S7 自己缺少 0.177 ns。应先通过 CSA 等优化释放预算，再尝试在 S7 注册 magnitude/LZD 或舍入准备信息。
- S5 可在 scale/abs 后与 LZD 之间拆级，但 S6/S8 当前也违例；仅增加已有 L9 的 post-scale 检测级不能自动解决所有瓶颈。
- S6 可在 MAX/net 与 barrel shift/符号恢复之间拆级；S8 可在 normalization/GRS 与 RNE/pack 之间拆级。
- 严格保持 8 级时，这些拆分需要在别处经实测节省/合并级数，不能只移动寄存器名字。
  所有 datatype、C、valid、last、reset 必须同步重新对齐。

### 独立 hold 修复

保留上述原始 run，新增 `dc_dp_top_11050215`，从它的 DDC 读取映射网表，只做 hold 优化。
入口 `prepare --hold-repair-from dc_dp_top_11050052` 要求验证门禁、库、机器绑定和全部最终约束与源 run 一致，拒绝未完成或无效源 run。
修复时临时增加 1 ps hold uncertainty，之后恢复原始 0.03 ns 再报告和导出；不放宽任何验收约束、不手改网表、不重综合 RTL。
修复已完成，[精简 JSON](dp_n12_1000mhz_hold_repair_20261105.json)：**flow_pass=true**。

- Setup WNS/TNS=0、违例 0，最差 slack +0.000003815 ns；各级最差值与上表完全一致。
- Hold WNS/TNS=0、违例 0，最差 slack **+0.001100987 ns（+1.100987 ps）**。
- 面积 **17742.090369 µm²**（组合 14139.924672；时序 3602.165697）；比首轮 1GHz 增加 4.091904 µm²，比 1.41GHz 减少 20.87%。
- LVT 非 blackbox 占比 **19.58%**，满足 20%；check_design=1、未解析 leaf=0、单时钟、未约束端点检查通过。
- 导出的 SDC 已核对：period=1 ns、setup/hold uncertainty=0.10/0.03 ns，无 case analysis、false path 或 multicycle path。

该结果证明单 DP 在所选 N12 TT 库及当前综合预算下满足 **1GHz、L8、II=1**；不包含布局布线或多 corner 签核。
保留两个 1GHz run，以区分首次残留 hold 违例与真实修复后的通过，不修改原始结果。
本批软件检查 30 项通过；RTL 仍是已完整回归的同一个冻结快照，未实施 CSA/前缀加法器优化。
