# E64 / 多精度单 DP · N12 同工况综合对比

本批实现专用 dp_lane_e、dp_group_e、dp_top_e，并完成独立 Verilator 验证和真实 DC 综合。E64 当前面积 **5545.893928 µm²**，相对本批多精度 DP 的 **18029.555835 µm²** 减少 **69.24%**。两者目标约束相同，但 E 尚有 **−0.307322 ps** setup 违例，因此这个面积降幅不代表 E 已通过 1GHz 时序。

用户已明确要求此次 RTL 验证和 DC 结果作为重要结果长期保存。有效运行均写入 retain.json；源快照、测试回执、原始报告及网表保留在本机，精简 JSON/本文进入 Git。无效首轮另存，未用于正式面积比较。

组合面积减少 72.15%，时序面积减少 57.70%。LVT 两者均低于20%。综合证据有效、时序通过和 Vt 配额分别判定；E 的 flow_pass=false，不能用四舍五入后的 0ps 宣称通过。

两者 link/check_design 通过，unresolved leaf=0，单时钟，check_timing 未发现未约束端点，S1–S8 寄存分类无 unclassified。剩余 check_design/库功耗建模提示留在原始日志中，不把它们当成真实负载功耗证据。

## E64 的流水时序

| 捕获阶段 | 最差 setup slack / ps | 通过 / 检查数据端点 | 代表路径 |
| --- | ---: | ---: | --- |
| S1 | +281.606555 | 818/818 | 输入 scale/type 解包与控制 |
| S2 | +198.632121 | 478/478 | 4×4 乘法→符号→第一层 pair |
| S3 | +174.904406 | 258/258 | 四项窄 lane 树 |
| S4 | +0.409245 | 190/190 | lane e2 小左移→组相加→abs |
| S5 | +0.028729 | 204/204 | scale/旁路→LZD |
| S6 | +0.257850 | 217/217 | 组+C MAX→净移位→符号恢复 |
| S7 | +0.021935 | 60/60 | 5 项 40 位最终树 |
| S8 | -0.307322 | 34/35 | sum→abs→LZD→规格化/RNE→FP32 |

唯一 setup 违例为 sum_q_reg_17_ → out_d_reg_27_，位于 S7→S8。arrival=1.003373981ns，required=1.003066659ns，slack=−0.000307322ns。该路径先进入 fp32_output 的符号/幅值逻辑，再通过 output_leading_detect，最后串联规格化、舍入和结果选择。E 前端的乘法/pair 与 lane 树已经通过，不能把这一违例归因于 FP4 元素乘法。

S1–S3 各有约175–282ps余量，S4–S7 最差余量则仅约0.02–0.41ps。它们不构成可直接给 S8 使用的相邻空级；本次也不把刚通过的数据级解释为有充分布线裕量。

后续优先保持接口/L8 做 S8 abs/LZD 与舍入路径的组合优化，或评估减少映射后的过度面积回收并保留明确时序裕量；每次改动重新回归和综合。若重划流水，先缩短 S7 多操作数树以释放预算，再讨论把部分规格化准备前移；不能直接把 S8 工作塞入当前几乎无余量的 S7。S3 的余量可用于单独评估将 e2 小左移从 S4 前移，作用主要是改善 S4，不会自动解决 S8。以上为依据实测路径提出的候选，尚未实施或宣称达标。
