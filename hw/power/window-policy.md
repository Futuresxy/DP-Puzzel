# 真实负载功耗的窗口与长度策略

2026-10-24 调研并定义。**结论：没有查到可直接适用于本项目的固定“标准测量拍数”。采用事件边界定义任务窗，并以增长窗口/分段检查确定稳定计算窗。K-PE/MN-PE微基准按用户最新决定，默认使用`96×1024 = 98304`对标量A/B数据，即98304 MAC，详见第8节。**配置状态仍为`planned`，不是已校准推荐或误差保证。

## 1. 调研依据及适用边界

Synopsys 强调应以代表实际工作模式的仿真生成活动，并保持 RTL、综合和门级测试向量及频率一致；SAIF 汇总不能完整保留事务时序相关性。这支持先固定数据/模式/时间边界，再测窗口，而不是只规定总拍数。[Synopsys 官方方法](https://www.synopsys.com/articles/understanding-power-profile.html)。

McPOWER 研究通过观察累积功耗并使用统计停止准则控制采样，而非对所有电路规定同一序列长度。它采用的随机激励/统计假设不能直接套用到有时间相关性的模型 trace；本项目只借鉴“根据稳定性/误差目标决定长度”的方法，不声称下面的阈值来自该论文或构成统计置信保证。[Burch 等，McPOWER，ICCAD 1992，作者提供原文](https://www.eecg.utoronto.ca/~najm/papers/iccad92-mcpower.pdf)。

本地参考项目使用 64 拍 warmup、1024 拍测量，但会循环 512/256 笔样本；它是局部持续计算基线，不能据此确定本项目所有阵列的充分样本量。初始 warmup/长度保留便于诊断对照，增长、分段与数据不足规则如下。[参考审计](reference-flow-audit.md)。

## 2. 三类窗口分别报告

| 类型 | 起止与用途 | 允许的解释 |
| --- | --- | --- |
| `task_complete` | 声明的 task_start 到完成事件；包含该边界内的配置、fill/drain、stall、转换和模式切换 | 该有限任务在 DUT 边界下的平均功耗、能量与完成延迟；作为任务主口径 |
| `steady_state` | 初始化/预热结束且设计进入指定稳定运行模式后的同相位连续区间 | 数据相关持续计算/特定状态 profile，不能代表应用平均占用 |
| `idle` | 对应初始化后的合法 idle 状态，保留声明的时钟/门控和输入保持策略 | 对应模式下 idle internal/switching/leakage；不等于只测 leakage |

`task_complete` 只包含其 DUT 边界内实际建模的资源；外部 SRAM/HBM/互连成本未建模时单列未知，不将任务名扩展成整芯片结果。无真实调度的 II=1 输入命名为 `continuous_compute_microbenchmark`，不能用该结果填 task 主栏。

## 3. 精确起止与相位

统一用 `[t_start, t_end)`，保存原始整数 ticks、timescale、scope 和实际 cycle period。仿真/转换器必须在同一半开边界计数，并保存 t_start 的完整初始状态；t_end 边界事件归于后窗。独立 TC 检查对齐这一规则，不以“约 N 拍”代替 duration。

对于 steady/idle，测试平台声明一个不与驱动/采样竞争的周期相位；起止取同一相位，`duration = N × actual_period`。这个相位从已验证 TB 协议选择并记录，不统一假设下降沿安全。直接 SAIF 的 start/stop 调用、VCD 裁剪必须通过边界实验确认一致。

对于 task，task_start 在该边界内第一项必需操作发起前记录；task_done 在最后输出完成握手/完成采样、必要 drain/idle 达成并处理完该时刻事件后记录。`t_end` 必须严格晚于要包含的最后转换；如用一个仿真 tick 保护，显式计入时间，不把最后输出跳变裁掉。是否要求 idle、数据搬入/搬出/转换属于任务边界，由该测试清单固定；没有 ready 的接口使用其 spec 定义的完成事件。

reset 与合法初始化默认不计入稳态，但如果任务起始状态要求冷启动/配置，它们属于 task 费用；另存分阶段窗口以解释开销。不能从任务结果中静默删除 bubble/stall/drain 来制造较低延迟。

## 4. 预热和初始化

先以合法接口完成所有功耗相关非复位寄存器的初始化，记录证据；不能 force 内部状态或按“该模式输出不使用”忽略 X。随后选择性进行稳态预热：

```text
warmup_cycles >= max(64, pipeline_latency_cycles + 2, state_settle_cycles)
```

`state_settle_cycles` 来自 spec 和实际填充/累加/buffer/模式状态条件，不能默认等于零。64 只是计划下限；状态未稳定则继续预热或判定不适用。每个模式/配置独立检查，不复制 PETile 的固定流水数。预热使用原 trace 的真实连续前缀并保留相关性，不允许跳过 K 累加前缀后把 C 随意设零。

task 窗不额外加一段被排除的真实任务预热来改变初始状态；若任务依赖已驻留权重/已填 buffer，声明该 warm-start 条件及所排除的成本。

## 5. 稳定计算长度：可执行化前的计划

计划参数见 [steady-state-v1.json](configs/windows/steady-state-v1.json)：

| 参数 | 起点与含义 |
| --- | --- |
| 候选总长度 | 1024、2048、4096、8192、16384 cycles，每段从同一个稳定起点取连续前缀 |
| 连续通过步数 | 2 次增长比较；最早在 4096 拍结束时有两次可检查步骤，1024 拍只作首个估计 |
| 平均 total 相对变化 | ≤2%；并同时检查 dynamic，避免 leakage 占优掩盖动态变化 |
| 平均 dynamic 相对变化 | ≤5%，其中 dynamic=internal+switching |
| 分段检查 | 每个新长度 N 另取前/后各 N/2 的精确 SAIF，比较同样 total/dynamic 阈值，防止累积平均掩盖漂移 |
| 真实独立片段目标 | 至少 3 个不同来源片段，每个片段内部做上述检查；跨片段不要求功耗相等，报告离散和采样范围 |
| 最大候选长度 | 16384 拍是本版预算上限；超出需改版策略/新 run，不能在未收敛时写 PASS |
| 隐式循环 | 禁止；显式 cyclic microbenchmark 独立标注，不能补足独立片段目标 |

长度比较定义为 `abs(P_N - P_previous) / abs(P_previous)`；分段比较以第一半平均值为分母。两值同为合法零时差异为零，一零一非零时不通过，不能用任意 epsilon 掩盖变化。原始功耗先归一为 W；每次更换 SAIF 都独立重置会话活动并保存报告。

在每个候选 N，记录 prefix 的总量和分量，以及两半各自的 PC 结果。仅当**增长比较和该长度两半比较都通过**才记一步；连续两步通过才选该片段的最短合格长度。所有计划片段测齐后保留各段选择长度；公平比较候选硬件/格式时使用足以覆盖全组的共同长度，并在共同长度重新核对。不得按功耗最小的窗口挑结果。

1024/2048/4096/8192/16384 拍在 1410 MHz 下约为 0.726/1.452/2.905/5.810/11.620 µs，仅帮助理解仿真规模；实际 run 按其冻结周期和时间精度换算，不固定为这些时长。

## 6. 短 trace、非稳态和任务窗

- 真实 task 比 1024 拍短：完整测它，不拉长、不填充；标 `finite_task`，steady convergence 为 `not_applicable`，不妨碍该有限任务自身有效。
- 稳态数据不足：标 `insufficient_trace`；可保留该有限片段估计，但不宣称 steady-converged。需要更多样本时回 `hw/test` 数据/验证流程补充。
- 至 16384 拍仍不稳定：标 `not_converged`，记录全部原值；先检查数据阶段变化与状态/映射，再决定分层采样或扩大预算。
- 只有一个真实来源片段：可报告该片段，标 `coverage_limited`，不伪造三个独立片段或总体模型代表性。
- 明显包含 prefill/decode、模式切换或不同活跃度的 trace：按真实阶段或完整 task 报告；不要删除变化区间以满足稳态阈值。
- idle：用合法保持/门控策略及同相位窗口；可复用稳态长度检查，但每 MAC 指标为 null，不把静态输入当成关闭全部时钟。

## 7. 汇总和不确定性

不同窗口的功耗以实际 duration 加权，`P = Σ(P_i T_i) / ΣT_i`；只对不重叠、边界相容且属于同一目标分布的窗口这样计算，不能叠加增长过程中的重叠前缀。独立片段分别报告，若用采样权重推广总体，权重需来自 workload 定义。

2%/5% 仅是窗口稳定性工程阈值，不是对物理准确度或 95% 统计置信的声明。相关 token、重叠窗口、同样本重复不满足独立假设；没有适当分块/统计设计时只报告片段离散，不给出形式化置信区间。首次真实试验应检查这些阈值、预算、预热及采样分层，再形成新的已验证策略版本。

## 8. K-PE/MN-PE：固定96×1024对标量数据

用户最新指定的多周期DP测试预算为：

```text
B_pairs = 96 × 1024 = 98304 对标量(A, B)操作数
B_macs = B_pairs = 98304 MAC
1 MAC = 1 次标量乘加 = 2 OP
B_ops = 196608 OP
```

一对指一次有效标量乘法使用的A/B配对，不是两个向量word、两个事务、bit或byte。两个操作数不再使MAC数乘2；scale、C/累加及其他元数据另行输入，不增加该预算。合法零值仍计有效MAC，padding和invalid lane不计。

当前默认为[dp-fixed-macs-v2.json](configs/windows/dp-fixed-macs-v2.json)。它适用于选定K-PE/MN-PE被测单元的固定工作量微基准，不替代真实应用task-complete；v1仅保留为历史planned配置。

### 8.1 完整调用与整除

本项目H16/Q32/E64每次完整有效PE调用分别处理16/32/64对，流水稳定且II=1时对应16/32/64 MAC每有效周期；不额外乘参考工程的归一单位。其他K-PE/MN-PE组织按实际profile确定容量：

```text
C_full = 整个被测DUT在当前模式一次完整调用处理的有效标量对总数
要求 B_pairs % C_full == 0
N_calls = B_pairs / C_full
accepted_pairs == completed_pairs == completed_useful_macs == 98304
```

| 每次完整调用容量C_full（对 / MAC） | 完整调用次数N_calls | 说明 |
| --- | ---: | --- |
| 16 | 6144 | H16参考模式 |
| 32 | 3072 | Q32参考模式 |
| 48 | 2048 | 整除算术示例 |
| 64 | 1536 | E64参考模式 |
| 96 | 1024 | 整除算术示例 |
| 128 | 768 | 整除算术示例 |

这些容量的最小公倍数为384，98304是其256倍。表格证明这些容量的整除关系，不替代尚待接入的实际profile检查；每个选定K-PE/MN-PE都须逐项核验。**v2要求完整调用，不接受向上取整、padding或partial tail**；新profile不整除时阻止该计划，不静默扩大预算。

MN-PE若一次顶层调用同时启用多个DP，`C_full`为当前模式下这些已选择、合法并发DP的有效MAC之和；每路都按其完整合法输入调用。不支持该格式的单元不强行启用，共享多模式资源的互斥模式不相加。若单独测一个DP，则显式改变DUT范围并记录；不能给每个并行DP各分配98304对后，仍称全DUT只完成98304 MAC。

有效调用按成功握手或spec接受事件计数；driver重试、stall时保持同一输入和气泡不重复计数。逐调用ID关联输入/输出，保存实际active lane、packing、并行输出数和完成量。`K_call`、任务总`K_job`、全DUT的`C_full`、II、调用次数与elapsed cycles分开；固定预算时不同容量的调用次数本来就不同。

### 8.2 测量边界

继续采用warm-start完整burst：合法初始化、预热并排空位于预算与测量窗外；确认流水为空后，在第一笔计数调用前开窗，恰好处理98304对，全部相应输出完成并达到必要drain/idle后关窗。窗口计入本次fill、计算、stall和drain，采用第3节半开边界。

C/累加初态及依赖仍来自真实测试，不为排空而force状态或发明flush协议。若无法满足入口状态，先按spec定义合法边界。II固定且无停顿时首末接受跨度为`(N_calls−1)×II+1`；H/Q/E在II=1时分别为6144/3072/1536个有效输入周期，完整测量还要计入实际流水、drain、握手和停顿。报告真实`t_end−t_start`，不把数据对数或调用次数当总仿真周期。

### 8.3 后续绑定数据与testbench

数据及参考RTL testbench归`hw/test`，具体路径由用户后续明确，当前v2的`test_bindings`为pending/null，不生成占位数据或预填假文件。执行前必须绑定实际数据清单、testbench、验证回执与hash，并证实输入格式、scale/C、布局、分组、原顺序及累加语义。

参考选定testbench设计门级回放，复用激励/driver、时钟与握手、事务顺序、golden/scoreboard、初始化和完成事件；DUT接入明确DC mapped Verilog与匹配标准单元模型，加入窗口控制和SAIF采集。testbench尚未指定时，只保留这项设计约定，不声称已存在可执行门级TB。

98304对是整个DUT的逻辑运算配对使用次数，合法广播/复用不等于新增独立原始样本；实际字节流量、唯一源样本数、物理输入项和复用次数分别记录。不同格式尽量覆盖同一原始运算集合，按验证过的合法分组调用。数据不足时先在测试侧补充并回归，不隐式循环或随机补齐。

### 8.4 稳定性和输出

预算整除保证完整调用的算术条件，不保证平均活动已经稳定。记录`fixed_work_burst`平均功耗、能量、实际时间及pJ/MAC；未经独立检查的steady-state状态为`not_assessed`。有稳态结论需求时另用第5节窗口检查，不为了凑固定拍数改变当前98304对预算；不同预算形成新配置/run，原始结果保持其来源与口径。
