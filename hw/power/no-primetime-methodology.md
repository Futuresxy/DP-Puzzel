# 无 PrimeTime、已有 DC 时的真实负载功耗分析方案

调研日期：2026-10-24。范围：单阵列/单核心；只定义方法、接口与验收要求。本轮没有启动 DC、OpenSTA 或仿真，没有测量本项目功耗，也未核验本机功耗功能的许可证。

后续决策：用户已选择 **门级真实负载 → SAIF → DC/Power Compiler**，N22 优先、N12 显式备选。当前流程与配置见 [power 入口](README.md)；本文保留原始工具比较，OpenSTA 不作为选定流程的自动后端。后续只读环境核查发现功耗接口，但许可查询超时；初次调研的“未核验”与当前“授权未确认”均不表示工具实际可用。

## 1. 推荐决策

**可以在没有 PrimeTime 的情况下完成真实数据驱动的综合后平均功耗估计。建议保留同一份负载活动，按已核验的工具能力选择后端：**

1. **DC 的 Power Compiler 功耗功能可用：**已验证 RTL → DC 冻结网表 → 真实负载门级回放 → SAIF → DC/Power Compiler 平均功耗分析。这是与现有 Synopsys 综合环境衔接较直接的早期设计流程。
2. **只有 DC 综合能力、功耗功能不可用：**同一网表 → 门级回放 → VCD/SAIF → 固定版本 OpenSTA + 匹配 Liberty。参考项目已采用这条路线，应吸收其验证与活动审计经验。
3. **需要更接近物理实现的绝对值：**在上述证据链上增加布局、CTS、提取寄生以及经验证的延迟门级活动。只更换报告引擎不能补齐这些输入。

Synopsys 将 Power Compiler 定位为 Design Compiler 环境中的功耗优化能力，并说明 SAIF 驱动的活动处理；这不证明某台机器的 DC 安装已包含可用功耗授权。实际功能和许可组合应以安装版本手册及成功 checkout 为准，不能从存在 `dc_shell` 或命令帮助直接推断。[Power Compiler 官方介绍](https://www.synopsys.com/implementation-and-signoff/rtl-synthesis-test/power-compiler.html)、[官方数据手册](https://www.synopsys.com/content/dam/synopsys/implementation%26signoff/datasheets/power-compiler-ds.pdf)。

**这里的“较为准确”应分成两件事：负载活动是否真实、物理电气模型是否完整。**真实输入只能解决前者的一部分；没有校准证据，不能承诺相对硅片误差为某个百分比，也不能保证不同配比的排序不受物理因素影响。

## 2. 各方法能支持的结论

以下分级是本项目建议的报告口径，不是工具厂商认证等级。

| 方法 | 输入与条件 | 可报告内容 | 主要限制 |
| --- | --- | --- | --- |
| 未注释活动的 DC `report_power` | 网表、库、默认/推导活动 | 初步探索估计 | 不能称为真实 workload 功耗 |
| RTL SAIF → 映射后网表 | 真实 RTL 活动、显式名称映射、内部活动传播 | 早期功耗趋势、优化指导 | 组合内部活动依赖推导，不能直接把 RTL 节点当作门级节点 |
| 零延迟门级活动 → Power Compiler / OpenSTA | 同一映射网表、真实事务、库、完整活动审计 | 综合后、指定窗口的平均功耗估计 | 缺少真实布线、CTS 和可靠的物理毛刺 |
| 延迟门级活动 + 物理寄生 → 适用功耗引擎 | 同源网表、SDF、SPEF、库、CTS、仿真兼容性证据 | 物理信息更完整的块级平均功耗估计 | 引擎模型、窄脉冲和相关性仍需验证；不自动成为 signoff |
| 合格的物理输入 + 签核功耗工具 | 经工艺/项目要求验证的完整流程 | 对应边界内的功耗签核 | 额外工具、授权和验证条件；本项目当前不具备此证据 |

Power Compiler 是较标准的 **Synopsys 综合阶段**选择，并不意味着一定比严格审计的 OpenSTA 结果更接近硅片。OpenSTA 的官方示例也给出门级仿真活动配合功耗估计的流程。[OpenSTA 官方功耗示例](https://openroad.readthedocs.io/en/latest/main/src/sta/doc/Examples.html)。

PrimeTime 主要承担时序分析；Synopsys 当前将门级平均、峰值、毛刺、时钟及签核功耗能力列在 PrimePower 产品中，并说明与 PrimeTime 的集成。历史 PrimeTime PX 的许可或命令不能直接套用于本机；本方案不依赖获得它们。[PrimePower 官方能力说明](https://www.synopsys.com/implementation-and-signoff/signoff/primepower.html)。

## 3. 必需输入与后续能力核验

| 输入 | 验收要点 | 缺少时的处理 |
| --- | --- | --- |
| RTL export 与验证回执 | 显式 export ID、`files.f`、逐文件 hash、指定配置的 SV 数值/周期 PASS | 阻止正式 PPA |
| DC 综合结果 | 源 export、网表/DDC、SDC、库/PVT、时序和映射报告、hash | 不复用仅有历史面积报告的目录 |
| 工艺功耗库 | 实际使用单元的内部功耗、漏电、引脚电容、状态条件及查表范围 | 缺失不能按零计算；区分功能库与功耗库 |
| 门级仿真模型 | 覆盖所有实例的功能、端口、ICG、顺序元件；延迟路线另查 SDF 支持 | 不以忽略缺失 module 的方式运行 |
| 真实 workload | 输入、量化/缩放、映射、时序、参考输出、版本与 hash | 随机激励只作压力/敏感性对照 |
| 功耗后端 | 安装版本、构建指纹、实际可用功能和许可 | 不能把帮助命令成功当作授权成功 |
| 物理数据，可后补 | CTS 后网表、SDF、SPEF、工艺 RC 角、提取来源 | 显式使用 pre-layout/理想时钟口径 |

DC 通常使用 `.db`；OpenSTA 路线需要可读取的 **Liberty `.lib`**。只有 DC 的 `.db` 不能假定 OpenSTA 能读取，也不能假定存在无授权的可靠转换方法。优先向现有库提供方获取同一 release、单元族和 PVT 的原始 `.lib`。

同名单元或相同端口不足以证明跨 release 的电气模型一致。优先使用配套 DB/Liberty/Verilog；确需不同 release 的功能模型时，记录差异并完成逐单元接口及功能验证，不能把参考项目的特例变成本项目默认规则。

后续接入挂载 EDA 后，在私有环境中核验 `read_saif`、活动报告、`report_power` 等本版本接口及实际授权。公开产品网页没有给出本机命令选项或许可证清单，本轮不填写具体 feature 名称。功能不可用时保留失败证据并选择 OpenSTA，不能用未注释报告替代。

## 4. 共同前端：构建真实且有代表性的活动

### 4.1 两种负载口径分别保存

- **持续计算窗口：**真实数值，连续喂数，测阵列的稳定工作状态，用于比较数据相关功耗。
- **任务完成窗口：**保留映射、fill/drain、K 累加、真实 valid/ready、存储停顿和模式切换，测声明边界内的完成时间与平均功耗，用于 DSE。

二者必须分别命名。固定 II=1、反复播放短样本是持续计算微基准，不等同于真实应用的占用率。默认随机数据、全零数据、翻转压力数据可以帮助诊断，不能代替这两类负载。

### 4.2 建议的采样来源

后续选定模型和任务后，固定 checkpoint、tokenizer、输入语料、seed、软件版本和模型运行参数，通过真实 forward 捕获相关 GEMM 的激活和权重。按研究任务覆盖 prefill/decode、不同层、Q/K/V/O 与 FFN、序列长度、batch 和 GEMM 形状；训练研究则单独定义前向/反向负载。它们是采样维度，当前不擅自固定模型或权重。

保留原张量与事务的对应关系：A/B 必须来自匹配输入通道和输出通道，C/累加状态必须符合实际 K 分块、bias、accumulator 和复用策略。不能为了提高样本“随机性”打乱时间顺序，导致权重复用、连续 token 相关性、scale 更新和累加切换全部失真。

BF16、FP16、MXFP8、MXFP6、MXFP4、NVFP4 分别保存编码、缩放粒度、舍入和转换版本。HiF4 在本项目确认规范前不生成所谓正式向量；参考项目支持某个同名实现不等于本项目已采用该语义。尽量从相同原始张量生成各格式输入，并单独记录质量可行性，不能把能效差异当作精度等价证据。

仅从真实权重/embedding 计算出的局部样本仍有使用价值，但应标注“模型派生局部算子数据”；它与完整 forward 的多层 trace 有不同代表性。参考项目的具体情况见[输入来源审计](reference-flow-audit.md#4-真实输入的代表性)。

### 4.3 回放、验证和窗口

1. 对指定 export 进行独立数值参考与周期验证；随后对匹配 DC 网表使用相同事务，核对结果、握手、延迟、计数、last、stall/resume 和 idle。能进行正式等价验证时补充，但本轮不假定工具可用；同负载门级比对不是所有输入上的形式等价证明。
2. 数据通路不复位时，采用设计允许的初始化/加载过程，使测量所需状态确定；不能强制内部节点为零。冷启动和模式切换本身若属于研究对象，应另外测量，不能统一排除。
3. 窗口明确定义 `[start, end)`、timescale、实际仿真时钟周期和作用层次。持续计算窗口排除 reset、合法初始化、warmup 与尾部 drain；任务窗口按约定包含必要 fill/drain/等待，并声明初始与完成边界。
4. 记录 accepted/completed 事务、有效 MAC、active/stall/idle 周期和 C/scale 更新。实际时钟受仿真时间精度量化时，使用真实周期，不能只读 SDC 中的目标频率。
5. 多个独立片段分别统计均值、离散程度和覆盖范围；逐步增加样本并检查均值及配比排序是否稳定。重复 512 个样本两遍不会变成 1024 个独立样本，不给出虚假的置信区间。

## 5. 路线 A：门级活动 → SAIF → DC / Power Compiler

建议后续实施顺序：

1. **冻结设计。** 从通过门禁的 export 完成 DC 综合，保存该 run 的网表/DDC、SDC、目标库、PVT、工具版本、面积与时序证据。
2. **生成门级活动。** 用匹配标准单元模型回放第 4 节负载。优先采集功耗工具支持的直接 SAIF；也可先保存 VCD，再经受验证的转换器得到同一窗口的 SAIF。
3. **独立分析会话。** 读取冻结的映射设计、同源库与约束；恢复活动前清理旧活动，读取 SAIF，指定准确 DUT 路径，保存名称映射/未匹配列表和活动报告。
4. **检查后报告。** 核对活动覆盖、实际活动率、时钟、单位和有效工况，再生成 internal/switching/leakage/total 及层次分解。`read_saif → 活动/映射报告 → report_power` 是步骤示意，具体参数以安装版本手册为准；不提供假装已验证的可执行 Tcl。
5. **测量时保持网表不变。** 不在读取该门级 SAIF 后继续 `compile` 或 power optimization。任何重映射、门控或 ECO 都产生新网表，必须重新验证与采集匹配活动。

SAIF 生成/转换也需验收：核对 scope、timescale、duration、总翻转数与 0/1/X/Z 驻留时间；按该版本语义检查各状态时间与窗口长度一致。用可手算的时钟、常量、门控和数据翻转波形验证转换器，再对真实窗口抽查 VCD 与 SAIF 统计。直接采集能保留多少额外统计，取决于仿真器接口与配置，应实际核验。

**直接 SAIF 与 VCD 转换并不完全等价。**Synopsys 说明，直接采集可以保留转换所得 SAIF 缺少的状态/路径相关统计；仅把文件后缀从 VCD 换成 SAIF 不会修复输入或物理模型。普通汇总 SAIF 适合窗口平均活动，不能恢复完整事件时间线。只有 RTL SAIF 时还需显式处理综合名称映射，不能声称它已经包含门级全部内部活动。[Synopsys 官方 SAIF 方法说明](https://www.synopsys.com/articles/understanding-power-profile.html)。

标准的收益是与现有综合数据库和厂商模型衔接、减少跨工具适配；不是自动获得毛刺、真实 CTS、布线或硅片误差保证。

## 6. 路线 B：门级活动 → OpenSTA

沿用相同网表、负载、窗口、PVT 和 SDC。后端读取 Liberty、网表、约束与 VCD/SAIF，使用固定版本的活动报告和平均功耗功能。OpenSTA 文档将该计算描述为基于活动与 Liberty 的静态功耗分析，功耗报告以 W 表示；它不是瞬时功率波形求解器。[OpenSTA 命令文档](https://opensta.readthedocs.io/en/latest/Commands/#report_power)。

工程上须补充：

- 将 DC→OpenSTA 的 SDC 变换保存为显式差异清单；不丢弃有效 clock、slew、IO delay、load、工况及非零线负载。未支持的关键约束应阻止正式结果。
- OpenSTA、仿真器、活动转换器均固定源码 commit/构建版本与二进制 hash。当前官网的命令选项不代表参考项目旧二进制支持；例如窗口裁剪可由前端完成，不依赖新版 `read_vcd` 选项。
- 继承参考项目的 VCD 大小写 identifier、窗口起始状态、叶单元引脚检查和无 X/Z 要求。
- 必须检查**实际用于功耗计算的活动率**，尤其是时钟、ICG、寄存器 CP，以及数据/控制热点。参考固定 OpenSTA 版本存在基于 slew 的活动限幅，100% annotation 仍可能低估；详见[时钟审计](reference-flow-audit.md#3-时钟活动与-100-ps-处理)。

本项目当前尚未建立该后端或选定依赖版本，本轮也未检查机器上是否已安装可用二进制。参考项目的固定版本可作为复现候选，不能未经验证自动选为正式依赖；后续按 `dependencies/` 与 `.deps/` 约定接入。

## 7. 想进一步提高准确度，应补什么

### 7.1 时钟：区分假设与实现

综合前/后 CTS 的时钟模型分开。CTS 前可定义有依据的理想源/叶端 slew，并在库有效范围内做敏感性分析；不能为了让活动审计通过就任意缩小 slew，更不能强制门控关闭分支保持满频。

参考项目的全时钟网络 100 ps 是比较假设，**不是实测叶端边沿，也不包含缺失的时钟树面积和电容**。它既改变可能被限幅的活动，又改变 Liberty 内部功耗查表条件。应保留原始/重算结果、假设来源和敏感性；有 CTS 后改用同源时钟树、寄生与传播时钟。OpenROAD 的 CTS 本身会插入时钟缓冲和子网，不能用仅设定 transition 代替。[OpenROAD CTS 文档](https://openroad.readthedocs.io/en/latest/main/src/cts/README.html)。

没有 CTS 时，也不能说“完全没有时钟功耗”：触发器内部时钟功耗、已存在 ICG 等仍应计算；缺少的是尚未实现的物理分布网络及相应负载。

### 7.2 线网电容：SPEF 与 SDF 分工不同

零线负载仍有库 pin capacitance 与显式输出负载，但没有真实片上 wire capacitance。仅靠标准单元面积不能恢复线网成本。

**SDF 提供延迟/时序检查信息；SPEF 提供寄生 RC。**给仿真器标注 SDF 可以改变事件到达和数字毛刺，不会自动给功耗引擎提供真实电容；只给功耗引擎 SPEF，也不会自动把零延迟 VCD 变成含延迟的活动。

若后续具备物理实施环境，可用商业流程，或在具备匹配 tech LEF、cell LEF、RC 规则和工艺支持时评估 OpenROAD。不能仅凭 `.lib` 或 `.db` 启动可信布局布线；换用其他公开 PDK 也不能冒充原工艺校准。布局估计寄生与布线后提取寄生要分别标记。[OpenROAD 寄生估计限制](https://openroad.readthedocs.io/en/latest/main/src/rsz/README.html)、[OpenRCX 提取输入与 SPEF](https://openroad.readthedocs.io/en/latest/main/src/rcx/README.html)。

### 7.3 毛刺：需要匹配的延迟仿真

优先验证能够完整支持本工艺模型/SDF 的事件仿真器；VCS、Questa、Xcelium 等仅在已有许可且完成兼容性核验时使用，不预设本机可用。Icarus 可作功能门级回放，但加入 SDF 不能只增加一个选项：需检查实际支持的 specify、条件延迟、互连延迟、顺序时序检查、最小/典型/最大值及 annotation 完整性。[Icarus 官方时序相关开关](https://steveicarus.github.io/iverilog/usage/command_line_flags.html)。

先用已知延迟的 reconvergent 小电路和 ICG/顺序元件验证：有无 SDF 时的到达时间、应出现/滤除的脉冲、时序违规及 X 行为，再扩大到设计。不能关闭 notifier 或忽略 X 来伪造有效活动；合法初始化也必须重新核验。

零延迟 VCD 可能丢失真实毛刺，也可能包含仿真调度产生的无物理意义事件，因此不是有保证的功耗下界。即使延迟 VCD 记录了脉冲，平均活动引擎对窄脉冲能量、状态相关功耗和相关性的处理仍有限，须在报告中披露；不固定乘一个“毛刺系数”。

## 8. 本项目建议的验收门禁

以下是待实施的要求；覆盖阈值属于项目建议，不是行业通用准确度保证。

| 检查 | 建议判据 |
| --- | --- |
| 来源一致 | export、验证、网表、SDC、库、输入和活动 hash 完整且匹配；过期结果拒绝发布 |
| 功能与周期 | 独立 golden 验证 + 同负载 RTL/网表比对通过，所有计数和协议成立 |
| 时序 | 保存 setup/hold、未约束路径、transition/capacitance 违例；未达标只能保留诊断估计，不列入宣称目标频率可行的 Pareto |
| 注释完整性 | 以实际使用的可观测叶单元功耗引脚为分母；建议总体至少 99%，关键时钟/使能/顺序引脚要求完整覆盖，例外逐项证明；另报工具自身统计分母 |
| 未知与常量 | 功耗所需活动无无法解释的 X/Z；常量、真实零翻转和缺失活动分开；非法/未建模状态不能按零 |
| 有效活动 | 按 `TC / 窗口秒数` 独立核对活动密度和 duty；记录首尾边沿容差，不能只看 activity origin 标签 |
| 电气有效性 | slew/load 在模型适用范围；记录理想/传播时钟、RC 缺失、外推和活动限幅；无法解释的限幅阻止正式结果 |
| 单位与总和 | 明确 W/mW、时间、电容和面积单位；`total = internal + switching + leakage`；层次求和避免父子重复 |
| 代表性与稳定性 | 多片段/任务、真实顺序、样本量和收敛记录；单一局部窗口的结论不扩展为整网 |
| 归档 | 小型摘要入 Git；网表、波形、全报告以受控 URI/hash 保存；论文关键输入可恢复，不仅保留最终表格 |

覆盖数达到 99% 不能排除剩余少量高功耗引脚的严重影响；必须同时检查未覆盖对象的重要性与活动来源。工具提供的注释比例、独立叶引脚比例、直接注释/传播/默认活动比例应分别保存。

时钟密度通常同时计 0→1 与 1→0，连续时钟约为 `2 × f`；不要把翻转密度误作每周期 0→1 概率。报告 Clock/Sequential/Combinational 与 Internal/Switching/Leakage 是不同分解维度，不能交叉重复相加。

## 9. 准确度验证与 DSE 交付

**先证明自洽，再测工具差异，最后谈物理校准。**后续选择有代表性的模式与负载，在相同网表、PVT、活动窗口、负载和时钟条件下比较 DC/Power Compiler 与 OpenSTA 的总量和分量。保留原始报告，先排查单位、库、活动、时钟、slew/cap、状态条件和默认活动，再解释残差。

两工具结果相近只能说明这些模型/输入下的一致性，不能证明接近硅片；不同也不能直接把某一个当真值。工具交叉核对和物理校准应使用不同标签。后续如具备合格 post-layout/signoff 证据或可分离边界的硅片测量，再验证误差；SPICE 小模块对照需同源晶体管模型/授权且有有限适用范围，本轮不执行。

建议向 characterization 交付的字段如下，属于字段约定，尚无 schema/实现：

| 字段组 | 内容 |
| --- | --- |
| 来源 | hardware/config/export/verification/synthesis/workload/activity/run ID 与 hash、工具 commit/版本、归档位置 |
| 方法 | `power_method`、`physical_stage`、`activity_method`、`clock_model`、`parasitics_source`、`glitch_model` |
| 工况 | 库/PVT、频率与实际周期、IO 负载、slew、窗口/层次、scope=array/core、included/excluded components |
| 数值 | internal/switching/leakage/total W、窗口秒数、有效 MAC、active/stall/idle、能量 J；未知项为 null |
| 质量 | 注释/有效活动审计、X/Z、时序、电气适用性、采样离散、交叉工具差异及物理校准状态 |

工具结果仅在证据完整后按仓库契约标为 `measured`，并明确其含义为工具估计而非硅片实测；`calibrated` 另需模型校准与独立留出验证。没有物理误差依据时，误差字段为 unknown/null。

任务能量按各阶段计算 `E = Σ(P_state × duration_state)`，平均功耗为 `E / T_task`；这里包含各阶段泄漏，不能重复相加。`pJ/MAC = E_J / 有效完成MAC数 × 10^12`；稳定窗口才可等价使用 `P_W / MAC_per_second`。以 2 OP/MAC 换算 TOPS/W。未知宏单元、SRAM、HBM、互连等成本独立保留未知，不能自动置零；阵列 profile 与已含该阵列的 core profile 不重复计入。

芯片级功耗由 `ratio_dse` 的资源与时间线组合：保留 stall/idle、共享存储、转换和并发情况，不把单核 II=1 功耗直接乘核心数。平均活动后端的峰值功耗字段保持 null；多个短窗口的最大平均值必须写清窗口粒度，不能称为真实瞬时峰值。

## 10. 后续实施顺序与交付位置

1. **能力核验：**挂载环境、版本、库、Power Compiler 实际可用性、仿真器能力，形成缺项清单。
2. **共同前端：**统一 export/RTL 验证门禁、网表来源、两类负载窗口、门级结果与活动审计。
3. **平均功耗后端：**Power Compiler 可用时先接路线 A，否则接路线 B；保留共用输入，具备条件后做交叉核对。
4. **代表性与不确定性：**增加独立 trace、真实调度、多窗口以及时钟/负载假设的敏感性，形成 DSE 可用 profile。
5. **物理增强：**有完整工艺与环境后补 CTS/寄生/SDF；重新采集匹配网表活动，再评估变化。

将公共驱动放未来 `hw/power/scripts/`，非私有配置放 `configs/`，负载来源放 `workloads/`，活动元数据放 `activity/`，完整 run 放忽略的 `runs/`；新 skill 仅放根目录 `.skill/<name>/SKILL.md`。本轮不新增 runner、配置默认值、依赖下载、仿真或 EDA 执行。
