## 已确认的方向与历史边界

目标是设计多精度点积计算单元 DP，并以经过验证的 DP 为基础构造计算阵列 Cube。先完成单元及阵列的实现和证据，再为芯片级配比研究提供输入；`hw` 与 `ratio_dse` 的职责边界保持分离。

用户已明确旧 DP 设计过时。本次重新定义 spec，不以旧实现补写新规格，也不把旧结构迁移作为默认任务。旧的六种 PE、H/Q/E 划分、SubPE/PEGroup 层级、原生 K、对齐窗口、11/18 级流水、端口和配置均不自动进入新合同。旧阵列讨论同样只作为待重新评估的资料，不能据其启动 Cube 编码。

旧源码、spec、配置、导出和实验记录保留为历史资料，其结果只证明原版本在原验证范围内的行为。新方案不继承旧版的通过状态；归档保留当前工作区内容；已有未提交实现修改在历史路径保留，不作为新设计成果。

用户确认维护三套代码：CModel、Chisel、独立手写的可综合 Verilog。Chisel 生成的 Verilog/SystemVerilog 是 Chisel 路径的构建产物，不是第三套手写源码。

## 一套 spec 的含义

同一个实现版本必须同时约束下列内容，不能只写最终的点积公式：

- **数值语义**：格式及其来源版本、元素编码、块缩放、特殊值、乘积与累加表示、每处对齐/截断/舍入、溢出及最终输出编码。
- **计算结构**：点积长度与支持模式、资源共享、规约顺序、内部数据表示，以及有意保留的硬件结构边界。
- **周期协议**：接收和输出的采样边沿、延迟定义、吞吐、valid/ready 或其他握手、配置生效、复位、气泡、停顿及排空。是否支持反压由新 spec 决定。
- **参数约束**：合法配置、最小/非二次幂尺寸的行为、非法配置处理、哪些参数在构建期固定、哪些允许运行期改变。
- **验收规则**：支持范围、测试矩阵、实现一致性要求、数学精度要求和必须保留的证据。

每个实现及测试报告引用同一 `spec_id`、`config_id` 和实现版本。三种语言可以采用不同的代码表达，但不能自行改变规约顺序、截断位置或流水合同。若优化改变这些合同，先更新 spec 和 CModel，再修改两套 RTL。

新 spec 文件骨架见 [规格索引](../src/spec/README.md)；格式集合、模块层级、位宽及周期等待用户定义，不预填硬件默认值。

## CModel 与数学参考各自负责什么

**数学参考**定义目标运算，用精确整数/二进制有理表示或有依据的高精度方法计算结果，评价有限位宽硬件方案引入的误差。它不复制硬件的每一级截断。

**CModel**执行 spec 定义的有限位宽算法，显式处理符号、扩展、移位、截断、舍入和特殊值。普通主机 `float`/`double` 的点积不能代替这一模型。建议采用 C++ 实现，语言标准和构建方式在实施前确定。

CModel 分为位精确运算和周期状态两部分。周期模型描述可观察的寄存边界、valid、握手、配置与复位状态，不凭空增加固定延迟来掩盖错误的状态推进。二态 CModel 无法表示的 RTL X/Z，由 SV 检查独立判错；无效且未初始化的数据通路值不参与数值比较。

必须分别报告：

1. **实现一致性**：两套 RTL 在规定的有效输出及控制观察点，与 CModel 逐位、逐周期一致；不能用 ULP 容差放行实现错误。
2. **数学精度**：CModel/RTL 相对数学参考的误差是否满足新 spec；门槛由新 spec 给出，不沿用历史数据集的 ULP 或命中比例。

两套 RTL 互相比对可以辅助定位问题，但二者一致不能代替独立参考与 spec 审查。

## 共用 testbench 的实现边界

共用的是测试用例、输入数据、调度序列、协议 monitor、scoreboard、精度规则和报告格式。各 DUT 只提供必要的端口适配；适配层不隐藏算法差异、不修正输出值、不补拍伪装周期一致。

建议先采用 CModel 离线生成期望值和周期记录、SV testbench 回放并比较的流程。相同场景分别运行 CModel、Chisel 导出的 RTL 和手写 Verilog 导出，按事务标识及定义的采样时刻核对结果。测试文件包含 reset、配置和气泡等控制事件；若新接口存在数据相关的 ready，按相同驱动策略推进，以实际握手记账，同时检查 ready 行为，不能把预先假定的接收周期当作事实。

需要实时联调时再增加经工具验证的 DPI/VPI 适配；它是共用环境的后端，不改变验收合同。当前 Icarus 流程只是可复用资源，不预先承诺任何新仿真接口可用。

测试矩阵覆盖合法配置、数值与 scale 边界、特殊值、严重抵消、定向与固定种子随机输入，以及连续有效、气泡、复位、模式切换、排空；若协议支持反压，覆盖停顿与恢复。逻辑元素到物理槽位的打包需有独立定向检查，避免 CModel 和 RTL 共用错误映射后相互“验证通过”。

既有数据与 TB 先核查能否表达新合同，再决定复用或重写。历史 `correct_961` 和 `batch512_ai_load` 不自动成为新版的充分验收集或真实负载来源证明。

## 源码、导出与 EDA

用户已确认以下目录；已创建文档骨架，尚无新实现代码：

| 位置 | 职责 |
| --- | --- |
| `src/spec/` | 新架构唯一设计合同；旧规格见 Git 历史 |
| `src/cmodel/` | 位精确与周期 CModel |
| `src/chisel/` | 新 Chisel 源码；旧源码见 Git 历史 |
| `src/verilog/` | 独立手写可综合 Verilog 源码 |
| 配置入口待定义 | 参数合同先写入 `src/spec/06-configuration.md`；历史配置见 Git 历史 |
| `test/` | 新版共用测试、数学参考、适配层及报告 |
| `hw/rtl/<export-id>/` | 两条 RTL 路径统一导出的只读构建快照 |
| `hw/dc_syn/`、`hw/power/` | 对指定快照执行综合、时序及活动功耗分析 |

手写源码与导出快照分开管理。两条路径各有独立 export ID、`files.f` 和来源映射；manifest 标明 `implementation_kind=chisel` 或 `handwritten_verilog`，关联相同 spec/config。仿真及 EDA 均读取显式导出，不直接读取随时可变的源码，不把两套同名 module 同时放入一个编译库。

沿用现有 LAB1 的轻量 RTL_ID 追踪规则，不在本次文档更新中恢复逐文件 SHA 要求；新导出 schema、签核门禁及其迁移在接入 EDA 前单独明确。不能只因为导出成功或历史验证通过，就将新版标记为可用于 PPA。

DC 综合的是两套 RTL，CModel 不参与逻辑综合。两条路径共用工艺库、PVT、时钟/IO/负载约束和分析入口，但独立保存面积、时序和 netlist。相同微架构不保证工具生成相同网表或相同 PPA。

功耗复用同一负载及窗口定义，每套实现分别回放并产生与其层次和 netlist 匹配的活动，不能互换 VCD/SAIF。随机正确性输入不能冒充真实 workload；需记录活动覆盖率、工况和工具限制。当前 EDA 环境不可直接执行，本阶段不运行 DC/power，不生成估算测量值。

## Cube 的后续规格入口

整体 spec 阶段，Cube 需与 DP 一起定义物理 tile、逻辑输出块、广播/脉动/其他数据流、preload/compute/drain、L0 容量及带宽、局部 accumulator、C/D 驻留、累加 RAW、K 拆分、尾块、排出与背压。尤其需区分 L0 层输出驻留与 DP/group 内输出驻留。

这些问题由新的 Cube spec 决定，不继承旧讨论中的固定组织或指令边界。Cube 使用已验证 DP 仍需要阵列级 CModel 和 RTL 验证，不能用单元通过代替阵列通过。
