| 参考做法 | DP 采用方式 |
| --- | --- |
| 模块/宏使用项目名前缀 | 模块 `dp_`，宏 `DP_`；不保留 `sn_` |
| 功能命名，DFF 使用 `ff_` | 采用，并加 S2→S3 等边界与功能名称 |
| 一行一个声明/赋值/普通端口连接 | 采用，DP 的 DFF 端口也逐行展开 |
| 功能层实例化 DFF，控制/数据分开 | 采用；原语内部保留行为级时序块，普通流水层不再散写时序块 |
| 异步复位/置位多种 DFF | 改为用户已确认的同步低有效复位；用 RESET_VALUE 参数覆盖控制初值 |
| 多 bit payload 使用使能 | 按有效数据更新语义采用，不以 ≥3 bit 作为正确性界限 |
| 固定常量/布局集中头文件 | 采用；参数化布局和局部计算保留 localparam，不将所有常量变成宏 |
| 禁止宏的无意义 localparam 别名 | 采用，明确类型转换或接口解耦不算无意义别名 |
| 内部打包后立即解包为功能名 | 采用；保留已有、具备参数化布局合同的扁平向量接口 |
| 组合逻辑只用 assign | 简单表达式优先；复杂译码、LZD、舍入允许完整 always @* |
| 禁止逻辑运算符 | 不采用全面禁令；真假条件和逐位运算分别选对应运算符 |
| 动态索引一律改为显式 one-hot MUX | 不采用全面禁令；先明确规模/越界/优先级，时序需要时再显式组织选择树 |
| DFF/enable 保证映射和 ICG | 不作保证；类型语义明确后仍需工具映射、约束、网表及测量证据 |
| 固定 15 项全绿回复和专用清理流程 | 改为按改动范围审查并报告未检查项；保留 DP 已有运行保留入口与规则 |

逻辑运算符按语言语义综合，并非天然导致仿真/综合不一致；例如多位 `a && b` 表示两个向量均非零，不能改成逐位与后取某一位。one-hot 选择也不是所有二进制 MUX 的等价直接替代，需要编码与互斥合同。基础 DFF wrapper 能统一复位/使能意图，不能绕过综合映射或自行保证最优 PPA。

模板独立验证使用严格 Verilog-2005，检查同步复位、复位优先、非零 RESET_VALUE、使能保持、连续传递、气泡及在途取消。它们不进入现有 DP 源清单；生产迁移仍按 [寄存器验收](registers.md#迁移验收) 执行。

本次模板验证（2026-11-06）：Icarus Verilog 14.0 devel `35a809d`，`iverilog -g2005 -Wall` 编译并由 `vvp` 执行；DFF WIDTH=3、RESET_VALUE=3'b101，边界示例 DATA_W=1/28，上述复位/使能/气泡/连续输入检查 PASS。临时 TB 与产物验证后清理；此结果不代表生产 DP 回归或 DC 通过。
