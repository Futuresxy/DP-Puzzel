# 从多精度 DP 到负载配比选择的研究路线

2026-11-10。当前优先完成[微架构正文](sections/03_architecture.tex)，随后将已有 DeepSeek 工作量分析迁移到最新硬件成本。研究主线是：**以共享 DP 提供多精度覆盖，以专用低精度 group 降低新增算力成本，比较 K/N 两种部署方式，再在资源约束下求不同精度负载的配比优势区域。** 配比是设计变量，最优选择由工作量、硬件成本和供数条件共同决定。

## 1 论证顺序与交付边界

| 环节 | 要回答的问题 | 当前依据与下一步 |
|---|---|---|
| 共享 DP | H/Q/E 如何共享乘法、对齐、规约和后端？ | 基础 v1.8 RTL、冻结回归、N12 综合与功耗；正文重写为 lane → group → DP |
| 专用化 | 增加 E 或 QE 时，哪些高精度资源可以删除？ | v1.9 E/QE lane/group；用完整 DP 成本及功能分解解释收益 |
| K/N 组合 | 相同 H/Q/E 峰值可以怎样实现？ | 三个 K 顶层已实现；N 使用完整基线、E64、Q32E64 的整数实例组合，阵列部分为解析模型 |
| 同能力比较 | 后端共享节省多少面积和功耗？付出什么带宽代价？ | 同批六架构测量支持单元成本比较；输入、累加端口及驻留容量分别推导 |
| 固定面积 | 单核增配与核心数量减少如何共同影响计算时间？ | 16×16 DP、基线占核心 30%、36 个基线核心构造等效预算 |
| 负载分区 | 哪种 H/Q/E 工作量组成适合哪种配比？ | 复用既有 simplex 和 DeepSeek 模型工作量，更新硬件表后重算 |
| 带宽与功耗约束 | 峰值扩展何时不再转化为负载收益？ | 明确约束边界后做敏感性分析，不预设扩展一定优于或劣于基线 |

第一层结果是单 DP 实测，第二层是基于实测单元的结构估计，第三层是尚未校准的核心池/负载解析模型。全文分别标识，不能把后两层写成整芯片测量。16×16 是本次面积模型的分析尺寸，不修改 `src/spec` 中既有阵列合同，也不构成阵列代码实施。

相关工作比较从功能语义入手，再记录原文 PPA 条件；见[五项相关工作核验](references/notes/dp_comparison.md)。不以不同节点、不同累加精度或不同硬件边界的绝对数值直接宣称领先。

## 2 微架构正文的核心叙述

1. **统一数值边界。** 每个 DP 完成一个输出的 scaled dot + C，浮点输出 FP32；L8/II=1，无跨请求 accumulator。共享模式的峰值不可同时相加。
2. **共享计算路径。** 每 lane 两套分段乘法器覆盖 T1H2Q4E8；T/H/Q 共用 group MAX 和局部移位，E 的四位定点重编码消除逐元素指数对齐，保留共享规约树。
3. **裁剪与重新切分流水。** E 专用 lane 的乘法/pair、窄树/e2、组和/abs 分别位于 S2/S3/S4；QE 保留 Q 的宽树并在 S4 消耗 e2。不能将“关闭宽通路”和“静态删除宽通路”混为一谈。
4. **公共组接口。** S5 输出未规格化幅值、符号、`A_raw`、`compare_exp`；S6 用比较指数求 MAX、用原始指数进行一次移位。
5. **共享后端扩展。** 新增 2/4 个 E16 或 4 个 Q8E16；S7 保持 carry-save 到双行选择后，只有一个最终 CPA。C 只加入一次。
6. **N 组合的独立输出。** 基线与低精度完整 DP 计算不同输出，后端和累加状态复制；通过整数实例匹配 K 方案的绝对算力。
7. **精度门控。** 本级有效/精度控制寄存更新，参与位随流水推进；非参与、数值零、特殊值分别处理。

论文正文说明设计理由和数据流，源代码级字段与回执通过本文件追溯，不把正文写成 RTL 操作手册。原稿的独立 H16/Q32 核、旧 MidGroup 层级、不同精度固定“25/26/28 位小数”等表述不代表当前实现，已从本章删除。

## 3 K 与 N 的同能力成本比较

令 F=H16Q32E64、E=E64、L=Q32E64，K126/K128/K148 为三个完整扩展 DP。以下是整数实例组合，面积直接相加；功耗只比较全部列在相应低精度模式下均活动的情况。

| 配比 | K 组合 | N 组合 | 总 H/Q/E MAC/cycle |
|---|---|---|---|
| 1:2:6 | 2 K126 | 2 F + E | 32/64/192 |
| 1:2:8 | K128 | F + E | 16/32/128 |
| 1:4:8 | K148 | F + L | 16/64/128 |

由同批完整 DP 成本相加得到：

| 配比与活动格式 | K 面积 µm² | N 面积 µm² | K/N 总功耗 mW | K 面积下降 | K 功耗下降 |
|---|---:|---:|---:|---:|---:|
| 1:2:6，MXFP4 | 37726.544 | 37974.381 | 28.835 / 29.429 | 0.65% | 2.02% |
| 1:2:8，MXFP4 | 21596.406 | 21809.259 | 17.595 / 18.233 | 0.98% | 3.50% |
| 1:4:8，MXFP8 | 27191.145 | 27860.337 | 28.789 / 29.582 | 2.40% | 2.68% |
| 1:4:8，MXFP4 | 同上 | 同上 | 20.563 / 21.414 | 同上 | 3.97% |

计算为 `A_N=Σ实例数×单DP面积`、`P_N=Σ实例数×该格式总功耗`，下降比例为 `1-K/N`；输入取上述 15 点 CSV 的完整精度。**这是实测单元成本的相加估计，不是相同 GEMM trace 下的 N 阵列功耗实测。** 同源输入的独立 DP 活动不能覆盖真实阵列广播、不同列数据相关性、布线和输出存储。E64 还保持原版本，比较对象应按上述具体实现命名。

新增算力成本可报告 `(A_j-A_F)/(K_j-K_F)` 与 `(P_j,f-P_F,f)/((K_j,f-K_F,f)ν)`。分母仅限容量确实增加的精度，不能用于 H。高精度模式下 N 的扩展单元不活动，但没有空闲模式功耗测量，不能把其活动功耗中的 leakage 直接当作完整 idle 功耗。当前结果支持先选择 K 作为负载研究主线；0.65%–2.40% 的面积差距也要求后续单独评估阵列结构开销。

## 4 输入带宽与累加状态分别推导

设基线活跃输出形状为 `m×n`，某一精度原生归约长度为 `k`，扩展倍率为 `r`。在理想行列广播、完整量化块、同格式等宽 A/B 条件下，令 `w(k)` 为每侧一条 k 元素向量包含尺度的 bit 数。例如 BF16 为 `16k`，MXFP8 为 `8k+8ceil(k/32)`，MXFP4 为 `4k+8ceil(k/32)`。RTL 每 group 的重复 scale 槽不应重复算作存储读取；末尾块和跨请求尺度复用需按实际缓存合同计算。

K 扩展使用 `m×n×rk`，N 扩展使用 `m×rn×k`，两者每拍 MAC 数均为 `rmnk`。每次发射的输入需求为

```text
b_AB,K = (m+n) w(rk)
b_AB,N = (m+rn) w(k)
```

若 `w(rk)=r w(k)`，N 因 A 复用少读 `(r-1)m w(k)` bit。若 A/B 宽度或尺度组织不同，分别写 `m w_A + n w_B`，不能套用等宽简式。

令累加器宽度 `c=32`，`u` 为维持流水和隐藏 RAW 延迟而交织的独立输出上下文数，则近端累加容量至少为

```text
S_C,K = u m n c
S_C,N = u r m n c
```

N 的累加状态增加 r 倍；这份容量必须由寄存器、L0C 或专用 accumulator memory 承担。当前 DP 不含跨请求 accumulator，同一输出的反馈延迟需上层调度解决。对没有反馈旁路的逐拍发射，八拍依赖通常要求交织至少八个独立上下文；实际读写相位可能进一步增加需求，不能以 II=1 推断 u=1。

DP 与近端累加存储间若每拍读 C、写 D，双向合计端口需求为 `2cmn` 与 `2crmn` bit/发射。即使部分和长期驻留于 L0C/TMEM，这个近端端口需求仍然存在。只有在所选边界**内**确有反馈与存储时，才能按每 τ 次更新向更远层级交换一次 C/D，得到摊销流量 `2cmn/τ_K` 与 `2crmn/τ_N`。

因此在共享带宽池、相同驻留更新次数 `τ_K=τ_N=τ` 且尺度线性条件下，

```text
b_total,N - b_total,K = (r-1)m [2cn/τ - w(k)]
```

该式解释输出流量和 A 复用的竞争；不是 N 总带宽必然更高的证明。若比较同一 GEMM 的最终输出，N 一次并行更多列、K 每个输出更快完成归约，驻留次数一般不同；当 `τ_N=rτ_K` 时，两方案每拍摊销最终 C/D 流量可相同。输出总字节数、同时存活的状态容量和近端读写带宽是三种不同指标。

Blackwell 的 TMEM 是累加状态独立存储的实际例子：官方 CUTLASS 文档说明 MMA accumulator 驻留 TMEM，epilogue 再载入寄存器。这支持讨论累加存储压力，不能据此断言 NVIDIA 因采用本文 N 扩展而新增 TMEM。[NVIDIA CUTLASS SM100 文档](https://docs.nvidia.com/cutlass/4.8.0/media/docs/pythonDSL/cute_dsl_api/utils_sm100.html)

## 5 固定面积的负载选择模型

按用户指定的 16×16 DP，设单 DP 面积为 `a_j`，基线阵列占核心比例 `α=0.30`，基线核心数 `N0=36`：

```text
A_T,j = 256 a_j
A_core,0 = A_T,0 / α
A_other = A_core,0 - A_T,0
A_budget = N0 A_core,0
A_core,j = A_other + A_T,j
n_j = floor(A_budget / A_core,j)
C_j,f = n_j × 256 × K_j,f × ν             [MAC/s]
P_j,f = n_j × 256 × p_j,f                [W, DP-only]
```

30% 仅锚定基线；默认固定非阵列开销，而不是给每种配比都重新强制 30%。保留已有 `peripheral_growth` 参数做敏感性分析。36 来自完整 Ascend 950 架构的 AI 子系统数量，每个含一个 Cube Core；不同产品可启用不同数量。它只确定等效核心池规模，不代表本模型复制了 950 的 die、工艺或全部功能。[华为架构白皮书，PDF 第 13 页](https://public-download.obs.cn-east-2.myhuaweicloud.com/ascend/%E6%98%87%E8%85%BE950%20NPU%E6%9E%B6%E6%9E%84%E7%99%BD%E7%9A%AE%E4%B9%A6.pdf)

当前新数据对应等效预算 496.592553 mm²，固定外围 9.655966 mm²/核心，核数 36/34/32/29。1 GHz 下的初步算术核对如下；这是充分供数、充分并行的峰值，不是端到端推理算力。

| 配比 | 核心数 | H TMAC/s | Q TMAC/s | E TMAC/s |
|---|---:|---:|---:|---:|
| 1:2:4 | 36 | 147.456 | 294.912 | 589.824 |
| 1:2:6 | 34 | 139.264 | 278.528 | 835.584 |
| 1:2:8 | 32 | 131.072 | 262.144 | 1048.576 |
| 1:4:8 | 29 | 118.784 | 475.136 | 950.272 |

令总有效工作量为 W MAC，`x_H+x_Q+x_E=1`。各阶段依次使用同一共享硬件，在理想供数条件下：

```text
T_j = W Σ_f x_f / C_j,f
E_j = W Σ_f x_f P_j,f / C_j,f
C_effective,j = W / T_j
```

现有脚本按 FLOP 计数，用 `2 MAC` 的相应换算保持一致即可。`x_f` 是计算量占比，不是时间占比；平均功耗不能直接用 `Σx_f P_j,f`。两候选时间相等的边界为 `Σx_f(1/C_i,f-1/C_j,f)=0`，能耗相等则为 `Σx_f(P_i,f/C_i,f-P_j,f/C_j,f)=0`。三角图分别着色，不合并为未经用户指定权重的单分数。

DP-only、固定频率和满利用率条件下，`P/C=p/(Kν)`，核心数量在单位计算能耗中抵消；外围功耗、idle、通信或停顿加入后不再普遍成立。Qwen 数据测得的模式功耗用于 DeepSeek 是活动代理，不是 DeepSeek 实测能耗。H 采用 BF16 功耗也不代表已测 FP16 功耗。

## 6 带宽和功耗约束的下一层模型

**等带宽。** 明确预算在每核心还是全芯片，以及 A/B、C/D 是否共用端口。扫描合法整数 `m_j,n_j`，同时满足输入带宽、累加端口、状态容量、面积和广播组整除约束；重新计算 `A_core,j=A_other+m_jn_j a_j+ΔA_storage/control` 与核心数。未知存储增量保持 unknown 或显式排除，不能补零冒充校准。

仅输入带宽受限、方形阵列、忽略尺度阶梯时，`2m_j k_j bν≤B`，因此 `m_j∝1/k_j`，单核峰值 `m_j²k_jν∝1/k_j`。这解释 K 增大后缩小 M/N 可能降低单核算力，但总芯片还受可部署核心数、固定外围和实际带宽分配影响；不能预设所有扩展配比都低于 baseline。共享 H/Q/E 的物理 M/N 必须固定，若某模式选择子阵列，需要保留未活动单元的面积和 idle 成本。

**功耗上限。** 先区分某精度阶段的峰值上限与整负载平均功耗。固定电压频率时，可通过限制同时活动核心数建立首个模型：

```text
P_pool,j,f(q) = P_shared + n_j P_idle,core,j
               + q [P_active,core,j,f - P_idle,core,j]
q_j,f = 最大满足 P_pool,j,f(q)≤P_cap 的整数，0≤q≤n_j
C_cap,j,f = q_j,f × m_j n_j,array × K_j,f × ν
```

这里阵列列数用 `n_j,array`，与部署核心数 `n_j` 区分。目前仅有 DP active 模式功耗，核心 idle、存储和外围数据尚未校准；可以先报告 DP-only 上限情景，不能称整芯片功耗约束已经闭合。不要未经测量用面积占比推算功耗占比，或套用 DVFS 曲线。1:4:8 的 MXFP8 单 DP 功耗较高，但每 MAC 能耗较低，故“功耗最高”不自动意味着限功耗下吞吐最低。

有限带宽和真实 GEMM 分析再引入形状利用率、K 尾块填充、RAW、fill/drain、preload/compute/drain。Roofline 的 min/max 只能作为上界或下界；实际传输重叠需要双缓冲与时间表支持。

## 7 现有负载成果与本轮写作顺序

用户确认 DeepSeek 工作量分析已经完成，沿用 [expected](data/expected)、[evidence](data/evidence)、模型固定版本及 `scripts/workloads.py`，不重新选择模型或改量化映射。旧 expected 是历史回归证据，不覆盖成新结果。后续从当前 CSV 更新 `hardware_n12.json` 的面积、频率和三模式功耗，保留旧输入与来源后再运行 `reproduce.py`；验证工作量坐标不变，核数、时间、能耗及分区允许改变。

用户进一步确认：暂用 MXFP4 功耗代理 NVFP4，后续补测后修正。两者原生 K 和峰值相同，替换这项功耗在当前面积/吞吐模型下只改能耗值和分区；若进一步计入格式相关带宽、转换或功耗上限，也可能影响受限延迟。这是明确的代理假设，不填写成 NVFP4 实测记录。本轮先完成微架构，暂不重算既有负载图。
