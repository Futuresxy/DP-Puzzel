## 比较范围

第五章六种 DP 面积与功耗为同批汇总的电路结果，N 组合为完整 DP 成本相加，未综合物理 N 阵列。1:2:6 比较 2 个扩展 DP 与 2 个基线加 1 个 E64；1:2:8 比较扩展 DP 与基线加 E64；1:4:8 比较扩展 DP 与基线加 Q32E64。仅报告新增单元均活动的模式，不假设关闭单元功耗为零。

基础 dp_top 使用独立修复后的 v1.8 网表；混合顶层和 Q32E64 为 v1.9；独立 E64 保留原实现并重新采样功耗。E64 在 group 处理局部微指数，保留宽 LZD、C LZD 和普通五项树；内部 E 扩展在 lane 内融合微指数、采用窄 LZD 和 carry-save 后端。因此 K/N 比较不是只改变组合位置的消融，不能将全部差额归因于共享后端。正文用电路结构解释这一差异，不引用版本编号。

## 负载模型与功耗代理

固定 16×16 DP/核心，基线阵列占核心面积 30%，以 36 个基线核心构造 496.59255257088006 mm² 等效面积预算。外围面积固定，四配比整数核心数为 36/34/32/29。此面积不代表 Ascend 950 实际芯片面积；模型也不等同于已实现阵列。

H 用 BF16 活动功耗。按用户确认，NVFP4 峰值与 MXFP4 相同，当前暂用 MXFP4 功耗代理 NVFP4；JSON 中标注 `proxy_mxfp4`，不声称 NVFP4 已测量。能耗图编码分区重合是代理假设的结果。第六章功耗来自 Qwen 活动，不是 DeepSeek 实测；结果只计 DP 活动，排除外围、存储、通信、停顿及格式转换。

新区域面积（基线、1:2:6、1:2:8、1:4:8 顺序）：

- 整数部署延迟：33.15%、7.94%、6.63%、52.28%。
- MXFP4/代理能耗：19.48%、2.84%、14.39%、63.28%。

区域面积不是应用概率。与旧稿相比，1:2:6 已具有独立优势区，相关论断已改写；旧历史结果未覆盖。

## 复核

`reproduce.py` 重建 42 个负载点、168 个配比评估、精确区域、5,151 点/目标扫描和两张图、三张表。`check_reference.py` 核对 609 个历史工作量字段，检查硬件输入等于固定测量 CSV 的导入结果，并独立计算部署数、各格式容量/功耗及全部时间/能耗。`test_parameters.py` 在临时目录检查核心数、阵列尺寸、面积比例、硬件成本、batch 和上下文改变后的响应。

重绘与检查不运行 EDA。完整模型结果在 `paper/data/results/`，由输入和脚本重建；正文、输入、紧凑表和图片进入版本管理。
