# 接口与协议

状态：接口需求已开始收集；尚未冻结 Bundle/端口或握手。

## 设计边界

分别定义 TensorCore、DP-Group、DP 的输入接收与结果输出边界。组内广播不允许把 DP 间逐拍转发藏入适配层；组间网络另行确定。组/阵列延迟与 DP 延迟分开记账。

DP 的输入至少需表达模式、A/B 有效元素、适用的 scale/metadata 及事务有效性。是否带 C、元素掩码、事务标签、ready、last 或其他控制，由后续协议决定，不提前固化为端口。

## 数据表示

- TF32 输入容器为每元素 32 位。有效数值位、上游转换和未使用位规则待确认。
- 其他格式分开定义数值编码位宽、物理容器宽度和打包槽位数；不能一律使用 `32/元素位宽` 计算并行度。
- `k_fp16` 决定基准配置，实际元素数量引用 `k_mode`；INT8 与 MXFP8 数量相同。
- 块 scale 以逻辑块边界映射到元素，不能随物理切片重新量化；HiF4 metadata 等待来源确认。
- 结果是否为 FP32、扩展定点表示或整数，以及 C/D 的边界，仍待定义。

## 协议待决项

需确认：接收事件及采样边沿；valid-only 或 ready/valid；配置和数据是否同拍；模式按事务还是整批生效；II；背压与排空；复位中止语义；混合模式允许范围。

INT8 更短路径可能与先前较长浮点事务同拍完成。若允许混合模式，必须定义独立结果端口、排序/仲裁或其他明确方案，并把相关等待计入对应延迟口径；不能简单复用一个输出 MUX 丢弃结果。若选择禁止在途切换，也需显式列入协议，不能默默继承旧 batch 固定模式。
