# 周期、流水与状态

状态：DP 浮点主方案目标 8 周期；固定流水、原子输入和无输出背压已确认。周期切分见 [主方案流水](dp/pipeline.md)，控制状态见 [DP 控制](dp/control.md)。1.41 GHz 尚无时序证明。

## 八级依赖分配

~~S1 解包 → S2 指数和 → S3 尾数乘 → S4 lane 移位对齐 → S5 lane 规约/基本组规约与 scale 融合 → S6 组间对齐平衡和 → S7 与 FP32 C 对齐累加 → S8 LZD、RM 舍入、FP32 norm/输出。此为逻辑依赖分配，逐级位宽和组合时序还需要收敛。~~

~~**v1.1 当前定义：** S1 全输入解包 → S2 指数和/MAX与尾数乘法并行 → S3 幅值对齐/E pair → S4 lane 树 → S5 两 lane 合并/scale/符号幅值输出 → S6 组+C 幅值对齐 → S7 全部部分和与 C 的树 → S8 FP32 RNE 或 INT32 回绕。见 [八级详细合同](dp/pipeline.md)。~~

**v1.2 当前定义：** S1 A/B/scale 解包并保存 C raw32 → S2 乘/指数/MAX → S3 共享幅值移位 → S4 lane 树 → S5 组和/scale，同时解包 C → S6 组+C 幅值对齐 → S7 总和 → S8 FP32 RNE/INT32 回绕；当前所有格式 L=8。

请求在上升沿 n 原子接收，主浮点结果 valid 在沿 n+8 观察。输出没有 ready。输入 A/B/C/scale/metadata 不齐时不启动新请求；这形成输入 bubble，已接收请求仍按流水完成，不能因此隐式增加该请求延迟。II=1 是设计目标，须依据硬件资源复用调度验证，不由 8 级本身推出。

~~INT8 并行度同 Q，保留整数乘法、分层累加和加 C；纯整数结果省去浮点对齐、归一化和舍入。精确 latency 由位宽和树深切分后决定，不预设少 2–3 周期；C/D 的整数位解释仍需冻结。~~

**v1.1 当前定义：** INT8 并行度同 Q，首版同样 L=8；绕过浮点移位/归一化/舍入，S8 输出 INT32。结构低零是可逆落位，不能导致整数精度损失。早出路径留作后续探索。

## 状态机与格式切换

~~一个活动会话固定一个 mode；不允许相邻未排空请求使用不同格式。收到 last 后停止接收，排空固定延迟流水，最后结果输出之后才能配置新 mode。输出端无背压，因此下游必须逐拍接收 valid 结果。保留 last；全局统一复位取消所有在途请求并清空 valid/last/mode 锁定。同步高有效 reset、首请求锁存 mode 为当前接口候选，详见 [控制](dp/control.md)。~~

**v1.2 当前定义：** 取消 DP 会话状态机；每个请求携带独立 datatype/ctrl，可以逐拍切换。last 只随结果传递；固定 valid 管线维持请求顺序，复位清除在途 valid/last，不存在待解除的 mode 锁定。详见 [控制](dp/control.md)。
