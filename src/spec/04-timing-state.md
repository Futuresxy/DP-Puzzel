# 周期、流水与状态

状态：DP 延迟上限及目标频率已确认；逐级划分与握手计数细节待确认。

## 硬约束

所有要求支持的模式与 `k_fp16∈{4,8,16}` 配置，DP 从输入到输出的内部计算须在 **8 级流水以内**，压缩计算深度，不沿用旧 11/18 级。`max_dp_pipeline_stages=8` 为约束上限，不是必须插满 8 级，也不是随意放宽的优化旋钮。

时序目标 `target_frequency_hz=1_410_000_000`，派生 `target_period_ns=10^9/target_frequency_hz≈0.709220 ns`。满 8 周期纯计算窗口约为 5.673759 ns，属于由目标时钟换算的预算，不是实测延迟或整个 TensorCore 的完成时间。

## 延迟计数建议（待确认）

建议以全部必需操作数被 DP 接收的采样沿 n 为起点，有效结果首次出现在定义的输出观察沿 n+L，`L≤max_dp_pipeline_stages`。输入寄存、格式转换、scale、规约、舍入和结果寄存，只要属于 DP 输入输出边界内就必须纳入，不把超预算阶段改名为 wrapper 来排除。

若有输出背压，应同时定义无停顿计算延迟与接收到实际输出传输的完成延迟；后者可能含等待，二者不能混报。具体边沿、观察相位和停顿策略仍需用户确认。流水级数与 II 分别记录，≤8 级不能自动推出 II=1。

## 短流水设计方法

先确定节点的数值与位宽合同，再比较解码、乘积/scale、对齐、规约、规范化/舍入在目标周期下的组合深度。可评估平衡树、carry-save 规约、并行指数路径与功能合并，但本轮不指定最终算术结构或逐拍排布。

寄存器数、时钟活动、MUX/广播扇出与组合毛刺共同影响功耗。减少级数不能以时序失败为代价，增加寄存也不能只看关键路径而忽略功耗；全部方案必须满足 L≤8。

## INT8 旁路

允许设计 `int8_bypass`，跳过不适用的浮点处理，以较短延迟输出。实际 `latency_by_mode[INT8]` 待设计和测量，当前不指定 2/3/4 级。旁路的 valid、标签、配置及结果仲裁须同步正确，浮点未选通路径应抑制无效活动。是否允许不同延迟事务交错见 [协议](03-interfaces.md)。

## 状态与复位

逐级寄存状态、有效推进、停顿保持、复位清空和 drain 规则待确定。每种模式/K 配置都须提供延迟与 II 表；INT8 较短输出不免除 1.41 GHz 的路径检查。
