# DP-Group：4×4 广播计算组

状态：组规模和组内无脉动已确认；广播网络和事务边界待定义。

## 计算组织

每组由 `group_rows × group_cols` 个 DP 组成，当前两参数均为 4，总计 16 个 DP。组内广播提供计算操作数，DP 不依赖前一个 DP 逐拍转发数据；不能把此组实现成 4×4 脉动阵列。

以矩阵点积为例，位置 `(r,c)` 需要 A 的第 r 行片段与 B 的第 c 列片段。因此 **A 沿行共享、B 沿列共享是候选广播映射**，还需确认物理接口和 scale/metadata 的作用域，不在本轮指定扇出树或寄存级数。

若采用该候选，一组一次完整 tile 的逻辑独立输入为 `group_rows*k_mode` 个 A 元素与 `group_cols*k_mode` 个 B 元素；这是条件性数据量推导，不是已承诺的每拍接口带宽。接收原子性、模式并行与 II 未确定前不计算峰值带宽。

## 广播与功耗要求

广播数据、scale、格式控制和 valid 必须按相同事务对齐。可评估在组边界缓冲、解码共享、有限扇出分发和无效输入保持，以减少复制和切换；只有语义相同的数据才允许共享解码。

广播本身不等于单级无限扇出组合连线。允许研究同步分发树或广播寄存级，但不得引入 DP 间的逐项脉动；额外寄存开销、延迟和功耗必须显式记录。组合广播路径也须满足 1.41 GHz 下适用的时序预算。

## 尚未确认

输入端口和打包、整组/逐行/逐 DP 接收、统一或独立模式、广播延迟、结果收集、输出次序、背压、C/D 累加位置及状态复位仍待定义。INT8 旁路若与浮点输出共端口，应处理不同延迟引起的冲突，不能丢失结果或隐式增大 DP 延迟。

组内验证必须检查全部 16 个输出坐标、广播选择和控制对齐，不能仅实例化一个 DP 后将其验证结果当作整组通过。
