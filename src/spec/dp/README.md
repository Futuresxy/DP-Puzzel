# DP：分组共享主方案、接口与后续对比架构

状态：用户已确定 T2H4Q8E16 基本组及 1/2/4 组构成 K4/K8/K16、scale 和 HiF4 metadata 按 16 个 E 元素切分、DP 内加 FP32 C 和无输出背压的固定流水。本轮主方案为 **近乎复用的分组对齐**。独立移位对齐保留为后续对比探索，暂不与主方案共用逐级流水合同。仍待定各级精确位宽、格式 scale 编码、RM 选项和 HiF4 metadata 数值语义，不生成数值通过结论。

## 主方案与对比方案

| 设计 | 当前阶段 | 目标 |
| --- | --- | --- |
| [T2H4Q8E16 分组共享](shared-align.md) | 当前详细设计与后续 CModel 的基线 | lane 内按 1/2/4/8 规约成统一 token；共享乘法、移位、规约和输出通路，尽量缩短到 8 周期 |
| [独立移位对齐](independent-align.md) | 后续对比探索 | 高精度整体比较指数、一次对齐；低精度按 scale 组形成点积再与 C 汇合，允许更多并行资源以换取较浅对齐路径 |

后续独立架构复用同一外部接口与数学参考边界，但其不同内部舍入顺序须由自己的 CModel 定义；当前先实现本分组共享方案。

## 容量层次

FP16 K4 基本组为 T2H4Q8E16；拆为两个 T1H2Q4E8 lane。K8/K16 并行组合 2/4 组，得到 T4H8Q16E32 / T8H16Q32E64。跨组平衡和的自然增长为 0/1/2 位。完整映射、紧密打包和 scale slots 见 [容量与 scale](layout-and-scales.md)。

## DP 接口与结果

每次原子接收 A、B、FP32 C 和当前模式所需 scale/metadata。所有浮点模式都在 DP 内完成 scale dot 与 C 最终累加，再由末段 LZD、RM 舍入和 norm 输出 FP32 D。A/B/C 必须同时有效才可接收，不支持输出 ready 背压；模式固定到 last 对应结果输出完成。`last` 的必要性及逐请求 C 的初始化/跨请求 RAW 合同仍待确认。详见 [接口](interface.md) 与 [控制](control.md)。

## 主方案八周期目标

浮点数据路径按照以下依赖切分候选周期：

1. 数据解包、TF32/FP16/BF16 兼容解码、scale/metadata 拆分。
2. 指数加法和乘积指数坐标。
3. 尾数定点乘法。
4. T1H2Q4E8 lane 内移位对齐。
5. lane 规约、两个 lane 合为基本组并融合适用 scale。
6. 1/2/4 个组结果的对齐、平衡规约。
7. 与 C 对齐并最终累加。
8. LZD、RM 舍入、FP32 norm/打包输出。

详细候选运算和最大 K 时序风险见 [流水文档](pipeline.md)。这是目标分配，不是已测可行性；位宽完成后要检查每级组合深度以及 1.41 GHz。INT8 走独立旁路，预期减少 2–3 周期，具体路径和输出格式待定。
