# DP：多精度点积单元

状态：功能与目标约束已确认；算术组织和逐级合同待定义。

## 计算范围

DP 负责一个输出位置的一次点积贡献。核心运算含 A/B 元素解码、必要的格式缩放、乘积与 K 方向规约；是否在 DP 中融合 C、保存跨事务累加状态，以及最终输出类型，尚待确认，不预设 `D=A×B+C` 的 C/D 边界。

支持集合为 TF32、FP16、BF16、MXFP8、MXFP6、MXFP4、NVFP4、HiF4、INT8；HiF8 不进入首版。详细规则见 [数值语义](../01-numerics.md)。支持格式是设计要求，不表示当前已实现。

## K 维度参数

以 FP16 并行点积项数 `k_fp16` 为基准，支持 `{4,8,16}`，供构建不同物理单元进行探索；默认选哪一档尚未指定。

记 `k_mode(mode,k_fp16)` 为该模式一次事务覆盖的点积项数。必须满足 `k_mode(FP16,k_fp16)=k_fp16` 与 `k_mode(INT8,k_fp16)=k_mode(MXFP8,k_fp16)`。其他倍率待用户确认，不能从 32 位 TF32 容器或元素存储位宽直接反推乘法器并行度。基准 K 不自动等于完整 GEMM 的 K 或软件指令 K。

## 数据路径与资源复用

HiF4 复用 NVFP4 通路是已确认方向；应明确哪些乘法、scale、对齐、规约、规范化资源共享，哪些因 HiF4 数值语义需要扩展。约 37 位保留目标不能仅用“比 35 多两位”替代位宽推导，也不能假定两种格式编码相同。

其余模式的共享结构等待比较功耗、扇出、MUX 深度和关键路径后选择。INT8 不需要浮点指数对齐与规范化的部分可旁路；复用浮点乘法资源与否仍待设计。未选中的通路应有明确的活动抑制方案。

**待评估的功能顺序**为：输入与解码 → 乘积/scale → 指数或数值对齐 → 规约 → 必要的 C 合并 → 规范化/舍入/输出。它不是已批准的流水切分，scale 的施加位置和 C 是否存在必须先由数值合同确定。浮点规约按哪种对齐顺序执行不能由综合工具或语言表达隐式决定。

## 精度和流水约束

遵守 [精度要求](../01-numerics.md)；各节点须写明符号表示、总宽度、小数点/anchor、增长、截断及舍入依据。整数运算不能被套用浮点的 25 位窗口而无声溢出。

遵守 [周期合同](../04-timing-state.md)：所有必需输入到有效结果的 DP 内部计算不超过 8 级，目标 1.41 GHz。流水预算随 K 和模式校核；INT8 可采用更短输出路径，具体延迟与输出仲裁未定。

## 实现出口

在实现前完成：格式编码/scale → 模式容量 → 各节点位宽和二进制小数点 → 规约/舍入顺序 → 输入输出边界 → 逐级寄存状态及 valid → 精度/周期验收。三套代码引用同一配置与合同；不以旧 PE 源码填补这些未决项。
