# T8H16Q64E64

新顶层 `dp_top_t8h16q64e64` 在当前基础 T8H16Q32E64 上并联四个 Q8 专用 group。四个基础组保持 v1.8 数值合同；扩展组使用 [Q lane](../lane/dp_lane_q.md) 和 [Q group](../group/dp_group_q.md)，不会参与 E、T/H 或 INT8 请求。现有六架构的规格版本与行为不随本次新增改变。

| 运行格式 | 基础组 | 扩展组 | 单笔原生 K |
| --- | --- | --- | --- |
| TF32 | 4 | 0 | 8 |
| FP16/BF16 | 4 | 0 | 16 |
| MXFP8 E4M3/E5M2、MXFP6 E3M2/E2M3 | 4 | 4 | 64 |
| MXFP4/NVFP4/HiF4 | 4 | 0 | 64 |
| INT8 | 4 | 0 | 32 |

A/B 物理端口各512 bit，group0..7连续占64 bit。Q使用全部8组；其他模式只使用低256 bit，高位允许携带毒化旧值且不会影响结果。每侧8个scale字节，Q64由两个逻辑K32 scale块映射到物理group0..3和4..7，不能把每组独立scale误作新的数学块。HiF端口保留混合顶层统一布局，只由基础4组使用。C为唯一FP32/INT32输入，每笔只加入一次。

顶层三路输入原子握手、逐请求类型、last透传、无输出反压、同步低有效复位均与当前混合顶层一致。Q扩展参与位逐级保存，不能用本拍输入类型控制旧事务的后端。扩展 `in_valid=req_fire & is_q`；不参与时寄存保持。后端分别处理：MAX无候选、对齐叶子为零、special贡献0、全负零归约贡献1。

| 阶段 | 本顶层处理 |
| --- | --- |
| S1–S4 | 基础前端与Q前端各自处理；C raw/控制延迟 |
| S5 | 八组共同时刻输出 token，C解包且不做LZD |
| S6 | 基础4组+C与扩展4组的候选MAX合并；唯一Emax广播，各源一次RTZ对齐与符号恢复 |
| S7 | 基础4源CSA4:2再与C做3:2；扩展4源CSA4:2；两支四行CSA4:2；按参与位同时选择两行；唯一CPA |
| S8 | 完整S44和的abs/LZD、FP32规格化/RNE，或INT32回绕 |

默认LOCAL_W=28、GLOBAL_W=40。九源规约位宽为 `GLOBAL_W+ceil(log2(9))=44`，浮点S7为S1I5F38；非Q请求的扩展四源为零，但最终CPA物理宽度仍44。高精度输出保持数值语义，不承诺新增MUX/CPA物理路径与基础DP相同时序。

本版本保持L8、II=1，不增加时间复用或跨请求内部累加。该流水是功能合同；1GHz及1.41GHz是否闭合需新快照的同工况DC检查，不能从既有Q64E128或仿真推定。当前任务不含新DC/功耗测量。

CModel profile为`t8h16q64e64`，配置默认启用`architecture_v19=true`，显式false拒绝（表示沿用已验证S5/S6/S7数值骨架，不是新增合同版本号）。完整验证入口：

