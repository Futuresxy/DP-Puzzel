# E192 / E256 扩展实现合同

两种顶层保持 **L8 / II=1**：S6 在一个流水级内计算统一 Emax 并并行完成全部来源的双向移位，S7 用 CSA4:2 将全部有效来源压缩到两行，片选后由唯一 CPA 求和。没有新增流水级或逐组时分调度。单周期是流水结构合同；能否达到目标频率由各自冻结 RTL 的 DC 结果判断。

v1.10 → v1.11：~~E192/E256 仅为待定流水候选~~ → 用户确认同周期移位、扩展支路 3/5 个 CSA4:2、L8/II=1 并授权实现与测试。Q-only 的 v1.10、基础 v1.8 及既有混合 v1.9 合同保留。文件名为已有稳定文档入口，正文现为实施合同。

## 1. 物理装配与接口

沿用[混合 DP 合同](mixed-precision-expansion.md)，基础四个全精度 group 显式启用 v1.8；扩展全部为 v1.9 `dp_group_e`，每组两个 `dp_lane_e`。扩展只参与 MXFP4/NVFP4/HiF4，T8/H16/Q32/INT8 K32 保持基础容量。

| 参数 | T8H16Q32E192 | T8H16Q32E256 |
| --- | ---: | ---: |
| 基础 / 新增 E16 group | 4 / 8 | 4 / 12 |
| 总 group 数 G / 含唯一 C 的来源数 N | 12 / 13 | 16 / 17 |
| A/B 各宽度 | 768 bit | 1024 bit |
| 每侧物理 scale 总线 | 96 bit | 128 bit |
| 每侧 HiF4 e1 / e2 | 48 / 24 bit | 64 / 32 bit |
| S6 每路有符号宽度 | S40 | S40 |
| S7 完整增长总宽 | S44 | S45 |
| 默认浮点 S/I/F | S1I5F38 | S1I6F38 |

`in_a/in_b[g*64 +: 64]` 为组 g，基础组占低 256 bit；C 始终只加入一次。固定包装拒绝改变组数、基础容量和 E-only 类型。默认 LOCAL_W=28/GLOBAL_W=40；验证还覆盖 27/40 与 32/64，宽度仍由公共参数推导。同步低有效 rst_n、A/B/C 原子接收、valid 每拍推进、无效 payload 保持、无输出背压均不变。

| 格式 | 逻辑 scale 粒度 | E192 每侧块数 | E256 每侧块数 | group g 的逻辑 scale 编号 |
| --- | ---: | ---: | ---: | --- |
| MXFP4 | 32 | 6 | 8 | floor(g/2) |
| NVFP4 | 16 | 12 | 16 | g |
| HiF4 | 64 | 3 | 4 | floor(g/4) |

上游按此广播到每组物理 scale 字节；不得将物理端口数解释为新的量化粒度。HiF4 e1 每四元素一位、e2 每八元素 lane 一位。

## 2. S1–S6 与全局对齐

前端不改变：E 的 S2 pair、S3 lane 树及 e2 融合、S4 group sum/abs、S5 scale/LZD22 并行运行。S5 输出 sign/U31 magnitude/S10 A_raw/S10 compare_exp/special/valid，与基础组及 C 同拍。

S6 的 `dp_mixed_global_align` 先对有限、非零、参与源求统一 Emax；base4+C 与扩展各自求 MAX 后合并。每路各自执行 `net_shift=A_raw−Emax` 的完整 S11 差值及一次双向幅值移位，右移 RTZ，随后恢复符号。默认组 U31 低补八零为 U39，C U32 低补七零为 U39，最终均为 S40。不能先按不同局部 Emax 求和再重新对齐，否则每源 RTZ 语义可能变化。

扩展 MAX 分支分别有 8/12 个来源；现有二叉树加最终合并的最深比较层数为 4/5。移位器逐来源复制，并未串联移位器；增加组数主要影响 MAX 深度、Emax 广播与负载。参与掩码、有限非零掩码、special 与负零摘要分别处理；闲置扩展寄存器中的旧特殊值不能污染 T/H/Q/INT8。

## 3. S7 的明确 CSA4:2 网络

先将 N 个 S40 叶子符号扩展至 `SUM_W=GLOBAL_W+ceil(log2(N))`。每个 CSA4:2 内部为两级 CSA3:2，无进位传播加法；carry 行已经左移并包含位权。所有中间行保留完整 SUM_W。

基础四组通过一个 4:2 得两行，再与 C 用一个 3:2 得基础两行。扩展压缩与基础分支并行：

| 扩展 | 4:2 分层行数 | 扩展支路 4:2 数量 | 基础两行与扩展两行的合并 |
| --- | --- | ---: | --- |
| 8 个 E group | 8 → 4 → 2 | 2 + 1 = 3 | 另一个 4:2 → 2 行 |
| 12 个 E group | 12 → 6 → 4 → 2 | 3 + 1 + 1 = 5 | 另一个 4:2 → 2 行 |

12 组先并行压缩三个四组块，前两个块合并，第三块两行透传到下一次合并。因此扩展支路最长为三个 4:2，8 组为两个；这不意味着三个/两个周期。用户所说 3/5 个指扩展支路；还需原骨架中的基础+C 压缩和一次分支合并，不能遗漏基础贡献。

参与片选同时选择 sum/carry 两行：E 请求取合并结果；T/H/Q/INT8 取基础两行。MUX 后唯一 CPA，S7 寄存总和；S8 完成原 FP32 RNE 或 INT32 回绕。INT8 不启用扩展，原坐标和输出切片保持不变。总的 4:2 实例数分别为 5/7，另有基础 C 的一个 3:2。

CModel 使用相同块连接生成 `trace[6].data.carry_save`，并独立验证最终 CPA 的有符号结果等于全部参与叶子的精确整数和。原 ext2/ext4 生成分支保留，避免改变其连接和行编码。

## 4. 验证、时序与数据来源

入口为两个同名 JSON config、`files_t8h16q32e192.f`/`files_t8h16q32e256.f` 和 `test/run_mixed_verilog.py --frontend <profile>`。新 profile 默认 architecture_v19=true，拒绝 legacy 算术和额外流水。每种独立导出冻结源码并建立完整数值/周期回执。

原生 E192 数据来自 `petile_full16_low32`，E256 来自 `petile_full16_low48`，各三种 E 格式 961 笔；目录为 `test/data/dp/<mode>/K192|K256/petile_low32|low48_native_961`，不截断或拼接较小 K。其余八种格式继续采用基础原生语料，共 10747 笔。数学 golden 用独立精确 Fraction 计算，并保留源 FP64 输出用于对照。

另外覆盖三个窗口、每个新增组独立贡献、全同号增长位、跨四组块抵消、各 scale 粒度边界、C 只加一次、NaN/Inf/负零、失活毒化、逐拍换型、气泡及同步复位。`test/check_mixed_csa.py` 对冻结压缩器独立测试 EXT_GROUPS=2/4/8/12、W=3/40/64，覆盖每叶正负极值、全同号、抵消、随机和失活选择。功能回执见 [E192/E256 验证记录](../../../../test/results/e192-e256-v1.11-20261112.md)。

面积、1GHz setup/hold、电气/VT、真实负载功耗分别由 `hw/dc_syn/records/` 和 `hw/power/records/` 记录。旧 E128 的极小正裕量不构成本轮通过证据；功能仿真也不能代替时序。当前不允许为收敛擅自增加 L9/L10，若需要改变架构应另行确认。

当前 DP 没有跨请求 accumulator；每笔为独立点积加 C。L8 的 II=1 指独立请求吞吐；将前一笔 D 外部反馈到下一笔 C 时仍有 RAW 间隔，不由扩大 CSA 解决。
