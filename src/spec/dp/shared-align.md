# 当前主方案：T2H4Q8E16 分组共享对齐

状态：作为当前 DP 微架构主方案继续细化；不是独立架构对比版已实现。`T2H4Q8E16` 对应 FP16 K4，每组含两个 `T1H2Q4E8` lane。DP 先消除 lane 内模式项数差异，之后按 1/2/4 个基本组配置形成 K4/K8/K16 结果。

## 1. 每个 lane 的工作

| 模式 | lane 项数 | 每个基本组两个 lane 合计 |
| --- | ---: | ---: |
| TF32 | 1 | 2 |
| FP16/BF16 | 2 | 4 |
| MXFP8/6 | 4 | 8 |
| MXFP4/NVFP4/HiF4 | 8 | 16 |
| INT8 | 4 | 8 |

两个 lane 在 S2 共享同一基本组 MAX，在 S3 完成统一坐标移位，S4 各自规约，S5 直接相加并融合适用 scale，输出独立 sign/magnitude 组 token。具体布局按 [数值合同](numeric-layout.md) 推导。

S6 对组与 C 一起做全局幅值对齐，S7 一次规约 group_count+1 项，K4/K8/K16 的树深为 1/2/3；组数本身的增长位仍按 ceil(log2(group_count)) 推导，完整总和须计入 C。

## 2. 资源复用目标

本方案主打复用乘法器及后续移位/累加通路，以功耗优先、面积其次进行评估。

每 lane 两组 8×8/8×4/4×8/4×4 的路由已明确，见 [乘法器共享](multiplier-sharing.md)；部分积重构仍需计入 S2/S3 时序。

尽量共享的资源候选：乘积尾数小乘法阵列、lane 对齐移位器、基本组加法器、组间移位/规约、scale/e1/e2 解码、FP32 C 最终对齐、LZD 和 RM norm。若为时序复制某些高扇出/宽移位资源，仍属于本方案中的有界资源复用，不等同于独立移位对齐架构。

解包先将元素整理为固定 [E/M/S 布局](unpack.md)，E2M1 指数/HiF4 e1 在此融合进定点幅值。块 scale 应先解码并在 16 E 项边界广播；能转换成固定指数/系数修正时与尾数路径并行预处理。随后在格式明确的定点坐标中融合剩余块 scale/e2，再进 K 组间和 C 合并；已经融入元素幅值的 e1 不重复施加。具体系数宽度、舍入点和 scale 可融合程度待数值合同决定。

## 3. 与独立对齐方案的边界

当前分组共享架构的接口、控制及 CModel 已完成首批验证。后续独立对齐架构作为第二套候选：高精度 T/H 乘积不先按 lane 分组移位，而在更宽的整体路径一次比较指数移位；低精度 Q/E 仍利用 16 项 scale/计算组。两套架构比较时使用相同 mode/K、FP32 C/D 接口、scale/metadata、周期限制和负载。因规约/截断次序不同，两套结果分别精确定义且各自对比数学参考，不假定互相 bit-exact。

独立方案当前没有本轮八级流水合同、模块或实现；其独立移位硬件是否部分复用、成本收益等进入后续对比研究，不阻塞当前主方案 CModel。

## 4. 物理共享与逐请求控制

T/H/Q 不各建一套移位器：每 lane 四个固定参数宽度实例，由本笔 ctrl 经输入 mux 选择，见 [移位器共享](shifter-sharing.md)。组 SOP、anchor 和控制同拍到 S5；C 只在顶层 S5 解包。逐请求 datatype 允许混格式在途，但每笔 A/B 仅同格式；共享资源面积按物理实例计一次，活动功耗按实际负载记录。

## 5. 当前组 token

S5 在 scale 后做 LZD 只计数，注册原幅值/原 anchor/z；S6 用真实 e 求 MAX 并按 z-d 一次双向移位。精确双单向方案保留作数值等价、面积/功耗/时序对照。共享 scale 乘法与完整小数点见[scale](scale.md)、[出口表](stage-formats.md)。
