# 当前主方案：T2H4Q8E16 分组共享对齐

状态：作为当前 DP 微架构主方案继续细化；不是独立架构对比版已实现。`T2H4Q8E16` 对应 FP16 K4，每组含两个 `T1H2Q4E8` lane。DP 先消除 lane 内模式项数差异，之后按 1/2/4 个基本组配置形成 K4/K8/K16 结果。

## 每个 lane 的工作

| 模式 | lane 项数 | 每个基本组两个 lane 合计 |
| --- | ---: | ---: |
| TF32 | 1 | 2 |
| FP16/BF16 | 2 | 4 |
| MXFP8/6 | 4 | 8 |
| MXFP4/NVFP4/HiF4 | 8 | 16 |
| INT8 | 4 | 8 |

lane 分别解码、形成乘积与指数/坐标，以 lane 内参考值对齐后定点规约；每个基本组将两个 lane 的 token 在公共坐标下累加，得到组部分和。所有模式都向下一级提供每组一个语义一致的点积 token，但内部物理宽度仍按格式派生。

FP16 K8/K16 分别并行使用 2/4 组；对 2/4 个组部分和进行同一层级的组间移位对齐与平衡相加，深度为 1/2，精确整数 sum 宽度相对一个组部分和增长 1/2 位。scale 分组和例子见 [layout-and-scales](layout-and-scales.md)。

## 资源复用目标

本方案主打复用乘法器及后续移位/累加通路，以功耗优先、面积其次进行评估。lane 内逻辑槽宽及乘法位宽依模式选择；共享 multiplier 的分段/子字方式是 datapath 方案待闭合项，不能假设同一硬件在各模式下都按一拍完成乘法。

尽量共享的资源候选：乘积尾数小乘法阵列、lane 对齐移位器、基本组加法器、组间移位/规约、scale/e1/e2 解码、FP32 C 最终对齐、LZD 和 RM norm。若为时序复制某些高扇出/宽移位资源，仍属于本方案中的有界资源复用，不等同于独立移位对齐架构。

解包先将元素整理为固定 [E/M/S 布局](unpack.md)，E2M1 指数/HiF4 e1 在此融合进定点幅值。块 scale 应先解码并在 16 E 项边界广播；能转换成固定指数/系数修正时与尾数路径并行预处理。随后在格式明确的定点坐标中融合剩余块 scale/e2，再进 K 组间和 C 合并；已经融入元素幅值的 e1 不重复施加。具体系数宽度、舍入点和 scale 可融合程度待数值合同决定。

## 与独立对齐方案的边界

本轮先完成该分组共享架构的接口、控制与 CModel spec。后续独立对齐架构作为第二套候选：高精度 T/H 乘积不先按 lane 分组移位，而在更宽的整体路径一次比较指数移位；低精度 Q/E 仍利用 16 项 scale/计算组。两套架构比较时使用相同 mode/K、FP32 C/D 接口、scale/metadata、周期限制和负载。因规约/截断次序不同，两套结果分别精确定义且各自对比数学参考，不假定互相 bit-exact。

独立方案当前没有本轮八级流水合同、模块或实现；其独立移位硬件是否部分复用、成本收益等进入后续对比研究，不阻塞当前主方案 CModel。
