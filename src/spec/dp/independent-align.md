# 方案 A：独立移位对齐

构建参数：`alignment_arch=independent`。目标是在尽量共享资源的同时，保留高精度一次整体对齐的浅路径；不要求各模式复制整套 DP。

## TF32、FP16、BF16

1. 并行解码 A/B 和 C，形成带明确指数/二进制小数点的完整乘积。
2. 对本事务的全部乘积和 C 做一次全局参考指数选择。
3. 各项相对同一参考移位对齐，随后平衡规约，完成最终规范化、舍入和打包。

不先把高精度按 1/2/4/8 粒度局部截断求和，再称为“一次全局对齐”。最终结果的规范化移位不算新一轮操作数之间的对齐，但其电路和延迟必须计入流水预算。

TF32 与 FP16/BF16 的并行项数不同，移位器个数也不同。可共享兼容的乘法子结构、部分移位器、控制和后级，但不能为增加共享强迫高精度改为分级对齐。共享后的选择网络和扇出须计入 1.41 GHz 路径与活动功耗。

## MXFP8 / MXFP6

原 scale 块为 32 个元素，当前三种 K 为 8/16/32，按原生 K 对齐时一次事务覆盖一个原量化块或其子片段。

先在该片段内对乘积进行指数比较、移位和规约，得到组内点积；随后融合该原块的 A/B scale，再与 C 进行最终对齐和规约。可按资源布局分发 scale，但不得改变原块归属。其 scale 编码、是否仅指数缩放必须由格式合同明确，不能只凭 MX 名称省略所需处理。

## MXFP4 / NVFP4 / HiF4

按 16 元素划分计算组，每组先完成局部点积，再融合原量化块广播来的 scale；所有已缩放组结果再与 C 对齐相加。

对能精确嵌入公共定点坐标的元素，优先评估窄整数形式乘积与局部规约，以避免宽浮点移位器。是否可做无损嵌入、移位范围和自然位宽须逐格式推导；HiF4 的局部层次缩放或 metadata 先按定义施加，不能因为复用 NVFP4 通路就省略。

低精度组数为 1/2/4，最终对齐处理组数加一个 C。MXFP4/HiF4 相邻组共享 scale 数值，NVFP4 每组独立；是否共享 scale 解码/scale 乘积可评估，但不同事务不能误用同一值。

## 共享边界与数值合同

- 高精度入口和低精度局部算术可独立，最终带符号规约、规范化/舍入/输出尽量共享。
- 已经用相同坐标完成对齐的结果不能为了接公共后级再发生一次无依据的截断；对齐后的数值/指数/special 一起传递。
- C 在高精度的一次全局对齐中参与；在块缩放路径中只参与 scale 之后的最终合并，不能被 A/B scale 再乘一次。
- 局部规约的增长位、scale 乘积扩展和最终 C 合并必须保留自然宽度。25/35/37 的作用点、保护位及舍入口径尚待确认，不凭此直接给出总线宽度。

[流水切分](pipeline.md)为浮点八周期候选。主要风险为 MXFP8/6 组内规约吞吐、低精度 scale 融合及公共最终规约/规范化时序；资源独立不代表必然低功耗。
