# DP 控制状态与周期级有效位

状态：会话内模式固定、原子输入、无输出背压和 last 后才能切模式已确认。状态名称与端口仍为实现前需审查的抽象协议。

## 控制状态

| 状态 | 输入请求 | 输出 | 说明 |
| --- | --- | --- | --- |
| IDLE | 不接收 A/B/C | 无 | 等待本会话 mode 配置 |
| RUN | 只有所需 A/B/C/scale/metadata 同时可用时原子接收 | 固定延迟产生 valid | mode 在整会话锁定，空输入形成 bubble |
| DRAIN | 不接受新请求 | 推进已接收的请求 | 收到 last 后，等待此前请求及末请求输出 |
| IDLE | 接收下一会话配置 | 无在途旧输出 | last 对应输出完成后进入 |

模式不能逐拍变化。INT8 和浮点模式不混杂于同一会话，因此不同延迟 tap 不会争用交错输出。是否需要独立配置 handshake、非法 mode 错误端口，待接口冻结时一并处理。

## 输入就绪及原子接收

只有 A、B、C 以及当前模式所需 scale/HiF4 metadata 同时就绪时，才产生一次输入 transfer；全部 payload 和 last 同拍采样。不对 A/B/C 分别入队。任何一路缺失时不启动一笔新 DP 计算，valid/ready 的精确组合表达由接口冻结。

空 bubble 不代表暂停已进入 DP 的事务。已接收 token 在内部流水每周期推进；下一个输入 token 可以独立停顿，不改变先前 token 的延迟。系统若要求全体状态随输入缺失停住，必须另行确认，因为这会改变固定延迟/II 合同。

## last 与 drain

`in_last` 若保留，只在一次原子输入 transfer 时采样并和对应 valid 一同穿过流水。收到 last 后进入 DRAIN，不再收新数据；已接收的所有事务继续完成。只有与 last 对应的 `out_valid` 结果出现并被下游按无背压合同消费后，才重新允许模式配置。

last 端口是否必要、下游接收保证及 C/D RAW/累加流语义仍待确认。不能在没有这些定义时宣称流会话生命周期已冻结。

## 周期约定

按寄存器更新前采样的上升沿定义周期：若原子请求在沿 n 被接受，DP 八级主路径在沿 n+8 产生对应输出 valid。每一周期的 valid/last 与数据 token 一起推进。DP 的 L=8 是主路径目标，允许输入 bubble；II 与可持续接收率须按所定资源结构核验，不从固定延迟自动推出。

控制复位须清空全部有效位/last，不能让部分结果在复位后输出。同步或异步、复位极性及各状态控制编码待接口/spec 完成后定案。
