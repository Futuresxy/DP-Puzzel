# DP 逐请求控制与有效位推进

状态：用户确认取消 DP 内会话锁定，允许相邻合法请求切换 datatype；last 只随结果传递。保留原子输入、固定八级、II=1 目标、无输出背压和全局统一复位。同步高有效 reset 与具体 ready 表达式仍为当前接口候选。

## 不设置模式会话状态机

DP 不再需要 IDLE/RUN/DRAIN、active_mode、last_seen 或用于切换精度的在途计数器。每笔 A/B/C 和 scale 类型在 req_fire 时形成不可变的 request control；在途请求各自按自己的格式计算。全局静态参数仍描述硬件能力、K 和位宽，不随请求改变。

这不表示电路没有状态：仍有八级 valid、与数据配套的控制/last 寄存器和必要的数据寄存器。上层可继续按同格式批次发请求以减少切换活动，但这种调度不再是 DP 正确性的前提；不得以 last 或前一笔格式阻止本笔合法请求。

## 控制的生成和逐级传递

S1 从 in_a_datatype、in_b_datatype、in_c_datatype 和两侧 scale datatype 生成 op_format、整数/浮点路径选择、活动 lane/product mask、scale 路径选择及输出类型。首版 A/B 必须同格式，重复字段可以在入口检查后合并为一个内部 op_format。字段宽度/派生由统一枚举和参数对象给出。

| 使用阶段 | 所需本笔控制 |
| --- | --- |
| S1 | A/B 解包子型、scale 解包类型、HiF4 使能；保存原始 C 类型 |
| S2 | 乘法器输入 mux/有效单元、指数加法与 MAX 活动掩码 |
| S3 | 共享移位器 mux、乘积 F、delta/RTZ、E pair/整数旁路、符号来源 |
| S4 | T/H/Q/E/INT8 树入口、静态低零与布局 |
| S5 | 组和/scale 选择、输出坐标、C 的 FP32/INT32 解包 |
| S6 | 全局浮点对齐或整数结构落位、各源坐标、有效掩码 |
| S7 | 对齐叶解释、特殊值合并、自然宽度的统一树 |
| S8 | FP32 RNE 或 INT32 回绕、out_d_datatype、out_last |

每级读取前一级与数据同行的 ctrl_q，不读取当前输入或某个可变全局模式。可以只携带一个紧凑格式码并逐级局部解码，也可以传递已解码控制子集；避免无需求地逐级复制所有原始枚举和宽度常量。共同 ctrl 管线可以在顶层/基本组保存并向同拍模块广播，不要求每个乘法器各存一份 datatype。后端记录广播扇出与布线成本。

模块参数是构建期配置，硬件 datatype 是逐请求运行时控制。固定长度、无状态反馈和统一 L=8 使混格式在途无需重新配置硬件；以后若某 profile 引入短旁路、时分资源或跨请求累加，必须重新定义顺序/冲突协议，不能直接沿用当前结论。

## valid、bubble 与 last

输入接收见 [接口](interface.md)。valid 每拍前移，未接收请求向 S1 注入 invalid。每级数据和 ctrl 在上一级 valid 时更新，无效时可保持以减少翻转；valid 仍必须推进并覆盖为零，不能因为输入缺失停住已接收请求。

last 仅在 req_fire 采样，与本笔数据/ctrl 一起推进。out_last 仅 out_valid 时有意义；可在无效级清零 last，禁止旧 last 与后续有效数据错配。last=1 后无需排空，不必等 out_last 后再接受新格式；连续多个 last 也只是连续多个流边界标记。

例如沿 n 接受 FP16、沿 n+1 接受 INT8、沿 n+2 接受 HiF4：各自沿 n+8/n+9/n+10 输出 FP32/INT32/FP32，三笔分别使用自己的 C 解包和输出控制。中间插入 bubble 只对应一个输出 bubble，不改变任一有效请求延迟。

## 时刻、复位与例外

统一沿前观察：沿 n 接收、S1 在 n 更新，S8 在 n+7 更新，沿 n+8 更新前采样结果，L=8。CModel step 返回本沿更新前输出并执行本沿更新；不得多加结果队列或混用 NBA 后采样。NaN/Inf 与整数溢出均不提前输出。

全局复位同时取消所有在途请求，清除每级 valid/last；复位生效时不接受请求、不报告有效结果。无效的数据和 ctrl 不要求全部逐位复位，但释放后必须由新有效 token 完整覆盖后才能使用。没有模式锁定状态需要复位；复位释放后可直接接受任意合法请求。精确复位极性/同步方式在 RTL 入口冻结前确认。

非法 datatype 元组不握手、由 TB 报告协议错误，不推进为有效计算。数值特殊编码若属于合法格式，则仍须接受并产生同延迟结果。没有跨请求恢复/异常 FSM。

## 取舍与验证要求

移除会话 FSM 允许连续混格式，省去排空气泡和模式锁定控制，但增加对逐级控制匹配的验证要求；频繁格式切换的动态功耗须单独实测，不能据状态数减少推断功耗必然降低。每个算术单元依据本级 valid/control 做输入隔离，不能按当前顶层格式关闭仍在处理旧请求的模块。

验证必须覆盖全部合法格式的前后相邻组合、FP32/INT32 C 切换、不同 scale 类型连续请求、last 后立即换型、连续 last、bubble 与复位。scoreboard 逐笔保存 datatype，不用一个全局模式解释所有在途结果。共享控制与所有基本组的数据/anchor 必须逐级同请求对齐。
