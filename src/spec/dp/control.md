# DP 控制状态与周期级有效位

状态：会话模式锁定、last 输出后切换、原子输入、无输出背压及全局统一复位已确认。下列首请求锁存模式和同步高有效复位为当前接口候选，不表示 RTL 已实现。

## 控制状态

采用最小配置候选：`in_mode` 随首个原子请求锁存，不增加单独配置事务。若后续指令接口需要配置握手，再扩展外部适配，不改变模式会话语义。

| 状态 | 输入 | 输出 | 状态转换 |
| --- | --- | --- | --- |
| IDLE | 允许首个合法原子请求，锁存 mode | 无旧会话结果 | 首请求 last=0 → RUN；last=1 → DRAIN |
| RUN | 只接收已锁定模式的原子请求 | 按模式固定延迟输出 | 接受 last → DRAIN；bubble 或流水为空仍保持 RUN |
| DRAIN | 不接受请求 | 所有在途请求继续完成 | `out_valid & out_last` 完成 → IDLE |

不得在最后结果输出的同一控制边界提前接收新格式。当前候选在该边界完成后回到 IDLE，下一次允许接收的周期才锁存新模式。非法模式/会话中途模式变化不握手，验证环境将其报告为协议违规，不能静默按另一模式解释数据。

## valid 与 last 推进

输入接收遵从 [原子握手](interface.md)。输入缺失仅插入 bubble，所有已接收 token 逐周期推进；数据寄存器可以在无效时保持，valid/last 的推进不得被下一笔取数停顿阻塞。

`in_last` 只在 `req_fire` 时采样，随后与该请求的数据、特殊值摘要和 valid 一起推进。`out_last` 仅与 `out_valid` 同时有效；无效输出不得结束会话。last 不生成额外输出，每个请求始终对应一个 D。

## 全局复位

所有子模块使用同一个全局 reset，不设置各级独立复位或模式切换复位。当前候选沿用 Chisel 默认接口的同步高有效 reset；异步或低有效复位须另行明确。

复位生效时统一回到 IDLE，清除 mode 锁定、全部 valid/last 和特殊值有效状态；不接收请求，不报告有效结果。复位中止所有在途请求，不等待 last、不继续 drain；释放后由新请求开始新会话。先前请求不得在释放后重新输出。

全局统一复位要求控制和事务有效性同时清空。无效数据寄存器的数值不构成结果，默认无需逐位清零；若系统要求数据位也清零，须另列需求及功耗/面积代价。

## 边界场景

- 单请求会话：首请求同时 last=1，直接进入 DRAIN，输出该笔 last 后回到 IDLE。
- last 等待操作数：仅拉高 last 而 A/B/C 不齐时不关闭输入，保持该笔控制直到真正接收。
- 会话中途断流：即使在途计数归零，也不自动解除 mode 锁定。
- NaN/Inf 末请求：保持模式固定延迟，特殊值不提前结束会话。
- 排空中复位：统一取消未输出结果，复位后不得残留 last。
