# DP 接口、输出与握手

状态：A/B/C 原子接收、固定流水、无输出背压、同一计算会话模式固定、FP32 C/D 及 DP 内 C 合并已确认。last 的必要性、RM 具体选项、复位极性及 scale/metadata 字段编码仍待确认。

## 计算边界与输出

每个有效请求携带一份完整配置 K 的 A、B 与 FP32 C。DP 完成该模式下的缩放点积、内部部分和归约、与 C 对齐相加，再归一化和 RM 舍入，输出 FP32 D。即 `D = round_fp32(C + scaled_dot(A,B))`；A/B scale 只作用于点积，绝不缩放 C。C 不在上层合并。

FP32 是所有浮点模式的对外结果。内部 25/35/约 37 位保留目标不能用 FP32 容器宽度替代。DP 返回一个结果对应一个已接收的完整 K 请求，输出 valid 和输入 last（若该标记保留）随同一事务传递。

INT8 的并行度与 MXFP8 相同，可旁路浮点 scale、全局指数对齐、LZD 和 FP32 norm，采用较短整数结果路径；是否仍通过 FP32 C/D 端口及其整数舍入/溢出解释需单独闭合。

## 端口合同草案

| 信号 | 方向 | 合同 |
| --- | --- | --- |
| `clock` / `reset` | 入 | DP 时钟与复位；有效极性/同步方式待定 |
| `a_valid`, `b_valid`, `c_valid` | 入 | 独立源的 payload-valid；需要的 scale/metadata 与对应 A/B 同步有效 |
| `out_a_ready`, `out_b_ready`, `out_c_ready` | 出 | 三个 ready 在接口阶段共用一个 `req_ready`，只允许原子 A/B/C 同时握手，不产生部分接收 |
| `in_mode` | 入 | 模式会话配置；一次会话中固定 |
| `in_a`, `in_b` | 入 | 紧密打包的逻辑输入，宽度依 `k_mode` 与槽位宽派生 |
| `in_scale_a`, `in_scale_b` | 入 | 每 16 E 元素一槽的 scale 映射；编码宽度待格式定义 |
| `in_hif4_e1_a/b`, `in_hif4_e2_a/b` | 入 | 每 16 元素组 4 个 e1 和 2 个 e2 项；字段位宽待格式定义 |
| `in_c` | 入 | IEEE FP32 编码，1 项/请求 |
| `in_last` | 入 | 标记数据流中本次会话/帧的末项候选；是否必需待确认 |
| `out_valid` | 出 | 与输出数据同周期有效；无 `out_ready`，下游必须保证可接收 |
| `out_d` | 出 | FP32 D；INT8 端口解释待确认 |
| `out_last` | 出 | 对应输入 last 的固定延迟副本（若输入 last 保留） |

上表是便于共用流水和 CModel 的协议形状；实现前需把 A/B/C 的源侧 valid/ready 语义精确定义为单一原子 transfer。不能让 A/B 已接收而 C 未接收。

## 原子握手

A、B、C 和本事务要求的 scale/metadata 必须同时可用，才接收请求；某一路未准备好时该组请求不启动。语义上一次 `req_fire` 原子锁存所有操作数和控制。只有一次请求入队，不为 A/B/C 设置会造成错配的独立队列。

DP 输出固定延迟且无输出背压，故 DP-Group 必须在对应输出沿接收结果；输出逻辑不得等待下游 ready。任何输入 valid 不齐时仅阻止新请求转移并形成 bubble，已经接收的事务继续按固定周期前进。固定延迟从原子请求接收沿起计。

## 模式固定与 last

同一活动会话中 `in_mode` 固定，不允许上一拍 FP16、下一拍直接切其他格式。只有接收了 last 并且该最后结果输出之后，才可进入空闲态并接受下一模式。`last` 标记一组流是否结束，不会改变单笔完整 K 的数学语义。

**待确认**：C 是每个独立点积请求的初始加数，还是流中逐项累加的前序结果；若后一情形，输入每笔是否仍携带 FP32 C，DP 无输出背压下如何约束 C/D RAW。last 是必要接口信号还是该 DP 事务天然一次性，需在控制文档一并确定。
