# 实现交付、时序与功耗优先设计

状态：现用 Verilog 已接入 N12 验证门禁与 DC，历史实测范围见 [时序记录](../../hw/dc_syn/records/README.md#历史记录)。真实负载功耗与新 E 专用单元尚无测量。SV 已冻结为 T8H16Q32E64 历史参考，不要求新功能导出或 PPA 与其同步。

## 1. 优化顺序

先筛选满足格式、精度、配置、接口、DP≤8 级和目标 1.41 GHz 的可行设计，再以 **功耗第一、面积第二** 选择电路组织。频率是约束，不用降低运行频率换取功耗优势后仍声称满足目标。不同吞吐、负载或活动窗口的结果不能直接排序。

功耗尚无用户指定 workload 和权重，因此当前不填单一功耗数或虚构排序。后续报告 workload 下 internal/switching/leakage/total、active/idle 分布及窗口；面积次级比较。能耗可以派生，但不替代功耗优先目标。

## 2. 电路设计要求

- 依据 valid、模式和实际使用范围控制寄存器更新；评估对未选通乘法、scale、对齐和规约路径进行 operand isolation，不能只屏蔽输出就认为内部无切换。
- 复用共享算术时同时检查 MUX、扇出、切换和时序；HiF4/NVFP4 共享为明确要求，其他模式组织待评估，不只按乘法器数量判断功耗。
- DP-Group 广播与公共控制减少复制时，应计入长连线、驱动缓冲和时钟树的成本；寄存广播不能被误称为 DP 间脉动。
- 平衡规约、适当的压缩树和流水合并可作为候选；必须用所选位宽下的实际路径验证，不保证“更少级数一定低功耗”。
- 数据通路复位、时钟使能和时钟门控依明确协议与工艺支持决定；不生成未经验证的门控时钟。
- 全部常量/参数集中定义，宽度采用足够精度下的最小合理值；不能在追求面积时降低用户的精度目标。

## 3. 时序与 PPA 验收

由 `target_frequency_hz` 派生周期，不能硬写一个近似周期代替配置源。工艺库、PVT、电压、时钟不确定度、IO 延迟、负载、时序例外及各模式的约束在实施前明确；不能把完整约 0.709220 ns 全当作无扣减的组合逻辑预算。

DC 检查所有实际使用的 DP、INT8 旁路、广播与输出路径，记录 critical path、WNS/TNS、未约束路径和目标达标状态。综合时序通过仍须注明是否尚无布局布线证据，不能等同于硅片达到 1.41 GHz。

需要比较的现用设计使用相同 spec/config、工艺、PVT、频率和负载，分别导出、验证、综合并采集活动。冻结 SV 不属于新功能必须评估的实现。不得互换层次不匹配的 VCD/SAIF；活动覆盖率和毛刺/寄生假设必须报告。没有适用验证证据的导出不能进入 PPA。

## 4. 实现前交付合同

补齐模块映射、版本与有效配置、导出 manifest/文件清单、签核门禁，以及结果关联。`hw/rtl/` 仍是唯一导出位置；不改变历史 LAB1 的轻量追踪记录。现用流程已接入工具/工艺；未测配置及新 E 设计的未知面积/功耗保持 unknown，不填零或估算测量值。

## 5. 八级基线与后续专用源

当前所有八级约束及 PPA 比较针对 H16Q32E64（T8）共享基线。后续在 S6 合并点接入 Q/E/QE 源时，需以独立 profile 记录实例化源、生成树深、额外 1–2 级及负载/活动差异；此处不启动专用源实现或 EDA，也不把基线放宽为十级。

## 6. 逐功能块面积/功耗

按用户要求，后续实现必须保留 [功能模块与统计映射](dp/implementation/resource-accounting.md)：解包、乘法、指数加法/MAX、移位、SOP 树、scale、LZD/norm/RNE，以及控制/mux/寄存的归属。对比的实现对应同一逻辑 ID，记录 RTL/网表层级优化与活动覆盖；按互不重叠的 cell 集合统计，不把父子 inclusive 成本重复相加。共享移位器/乘法器的面积只计一次，各格式动态功耗分负载窗口测量。当前仅定义统计合同，不启动 DC 或功耗分析。

## 7. 合并双向移位与双单向对照

当前首选 S5 在 scale 后仅计数、S6 一次双向移位；两段单向移位作为同数值算法的对照。比较完整 DP 及功能块面积、动态/静态功耗、关键路径/频率、II 和延迟。必须包含 LZD、计数/anchor 寄存、方向 mux/路由及备用 L9 的时钟负载；不能只对比 barrel 数量。相同窗口/格式/K/工艺/PVT/负载条件下才比较，时序不满足时如实报告。新对照实验须按当次授权执行；历史测量不自动覆盖新设计或新参数。
