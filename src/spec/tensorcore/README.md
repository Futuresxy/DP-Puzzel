# TensorCore：16×4 DP 阵列

状态：物理组织已确认；组间连接、存储和调度待定义。

## 1. 组织与坐标

四个 DP-Group 沿竖直方向拼接，每组 4 行×4 列 DP，总计 16 行×4 列，即 64 个 DP。本轮以行对应 M、列对应 N 作为文档坐标约定，尚不据此定义软件指令输出块。

```text
TensorCore（16 行 × 4 列 DP）
┌─────────────────────────────┐
│ DP-Group[0]：4×4，行  0… 3 │
├─────────────────────────────┤
│ DP-Group[1]：4×4，行  4… 7 │
├─────────────────────────────┤
│ DP-Group[2]：4×4，行  8…11 │
├─────────────────────────────┤
│ DP-Group[3]：4×4，行 12…15 │
└─────────────────────────────┘
               列 0…3
```

设 `group_rows`、`group_cols`、`group_stack_count` 为具名结构参数，当前配置分别为 4、4、4。派生 `tensorcore_rows=group_rows*group_stack_count`、`tensorcore_cols=group_cols`、`dp_count=tensorcore_rows*tensorcore_cols`。组内 `(r,c)` 对应全局 `(g*group_rows+r,c)`。图中的 16、64 和行号是这些关系的展示，不得在实现中重复硬编码。其他阵列形状尚未列为验收配置。

## 2. 组间连接边界

组内采用 [广播计算](../dp-group/README.md)，DP 之间没有逐拍传递操作数的脉动链。**组间是否广播、寄存转发或脉动尚未确定**，竖直拼接仅确定空间组织；不得恢复旧版“组间脉动”的默认假设。

同列 B 数据在多个组间可能存在复用机会，但实际网络、广播级数、源端口数、时钟/valid 对齐、布线扇出和功耗须另行确定。阵列总输入带宽不能仅按 64 个 DP 的端口宽度直接相加，也不能在缺少复用网络合同时假定零成本广播。

## 3. 后续必须完成的合同

- 逻辑指令与物理 tile 的映射，M/N/K 切分和尾块处理。
- L0 A/B/C 与 scale/metadata 的布局、容量、带宽、端口及初始状态。
- preload、compute、drain 的状态与周期；能否重叠必须有资源和缓冲依据。
- C/D 和本地 accumulator 的位置、跨事务累加 RAW、反馈与驻留合同。
- 输出收集、格式转换、排序、背压及组间同步。
- 每组的配置作用域、模式切换以及 INT8 提前输出的对齐规则。

DP 的 ≤8 级不自动是 TensorCore 端到端延迟；广播、缓冲、排队和排出必须单独计数。整体逻辑目标为 1.41 GHz，除 DP 外还需验证组内广播、组间网络及输出路径；当前无达标证据。
